### Что уже проверено — не повторять

Прошлая итерация закрыла ложные версии причины, замеры сохранены в
`plan/done/review-multilevel-2/stage_7.md` (§ «Что выяснилось при исполнении

- **Не геометрия карты.** Хост и реплика читают стены ОДНИМИ склеенными

### Причина (установлена, но не устранена)

Разное **разрешение контакта**, а не разная стена.

Хост (`core/src/tank.rs:160-185`): Rapier, корпус — `cuboid(4, 3)`
(`model.size = 2` → 8 × 6), `soft_ccd_prediction(width.min(height)) = 6`.
Rapier строит СПЕКУЛЯТИВНЫЙ контакт, пока тела ещё разведены, ведёт
многоточечный манифольд и решает скорости ДО интеграции позиции.

Реплика (`core/src/client/predictor.rs`):

1. `step_inner` (:707) интегрирует позицию скоростью (:768-776) и только
   потом зовёт `resolve_world(dt)` (:777);
2. `resolve_world` (:831) собирает контакты по УЖЕ перекрытому OBB —
   один контакт на пару, вектор минимального выталкивания
   (`obb_vs_obb` / `collect_block_contacts` в
   `vimp-engine-core::client::collision`);
3. дальше `separate_bodies` один раз на контакт и `SOLVER_ITERATIONS = 4`
   (:48) проходов `apply_contact_impulse`
   (`vimp-engine-core::client::rigid_body:118` и `:136`).

Следствия: на скорости 148.85 ед/с танк за шаг 1/120 уходит в стену на
1.24 ед. и реагирует уже изнутри; единственная точка контакта даёт другое
плечо, чем манифольд Rapier, — отсюда `angvel`; при глубоком касательном
перекрытии ось MTV вообще может оказаться другой.

## Этап 2. Спекулятивные контакты в реплике (E, затем T)

Это главная правка. Реплика обязана видеть контакт ДО перекрытия, как
Rapier, и решать скорости до интеграции позиции.

### 2.1 Движок: контакты с зазором

`packages/engine/core/src/client/collision.rs`:

- `obb_vs_obb(a, b)` сейчас возвращает `None`, как только перекрытие по
  любой оси `<= 0` (строка с `if overlap <= 0.0 { return None; }`).
  Добавить вариант с предсказанием: `obb_vs_obb_within(a, b, prediction)` —
  ось с максимальным ЗАЗОРОМ выигрывает, `Contact::depth` становится
  знаковым (`> 0` — проникновение, `< 0` — зазор), контакт возвращается,
  пока зазор `<= prediction`. Старую функцию оставить обёрткой
  `obb_vs_obb_within(a, b, 0.0)` — её зовут игры и тесты.
- То же для сбора со стенами: `collect_block_contacts(obb, blocks,
  prediction)`. Сигнатура публичная и уже используется танками —
  это ломающее изменение, значит минор крейта.
- Точку контакта считать той же `contact_point` с
  `CONTACT_MANIFOLD_RATIO`: смешивание вершин грани уже сделано.

`packages/engine/core/src/client/rigid_body.rs`:

- `separate_bodies` должен игнорировать контакт с отрицательной глубиной
  (разводить нечего).
- `apply_contact_impulse` — учесть зазор: сейчас импульс не считается при
  `vn >= 0.0`. Для спекулятивного контакта порог сдвигается на скорость
  закрытия зазора за шаг: `bias = -depth / dt` при `depth < 0`, импульс
  считается от `vn - bias` и зажимается снизу нулём, чтобы контакт не
  «притягивал». Функции нужен `dt` — добавить параметр (ломающее
  изменение, тот же минор).
- Восстановление `restitution` на спекулятивном контакте применять только
  к части скорости, которая реально закрывает зазор, иначе тело отскочит,
  не коснувшись.

Тесты движка (рядом с существующими в тех же файлах):

- контакт с зазором `0.5` при `prediction = 1.0` найден, `depth < 0`,
  нормаль та же, что у перекрытия на той же паре;
- `separate_bodies` не двигает тела на отрицательной глубине;
- тело, летящее в стену со скоростью, за шаг перекрывающей зазор,
  останавливается У стены, а не внутри неё (сравнить с Rapier тем же
  приёмом, что `map::tests::soft_ccd_prediction_keeps_penetration_shallow`);
- прежнее поведение при `prediction = 0.0` бит в бит (регрессия на
  существующих тестах `collision`/`rigid_body`).

### 2.2 Танки: порядок шага

`core/src/client/predictor.rs`:

- `resolve_world` вызывается ПОСЛЕ интеграции (:777). Спекулятивный контакт
  требует обратного порядка Rapier: собрать контакты на позе НАЧАЛА шага с
  запасом `prediction` → решить импульсы → интегрировать позицию →
  один проход позиционной коррекции на остаточное проникновение.
  Развести `resolve_world` на две части (`collect_contacts` +
  `solve_and_integrate`) и переставить относительно блока интеграции
  (:768-776). Комментарий у блока интеграции про «эмпирический порядок
  Rapier, зафиксирован паритет-тестом» обязан остаться верным: позиция
  по-прежнему интегрируется скоростью ДО демпфирования.
- `prediction` брать тем же числом, что хост: `min(width, height)` корпуса
  (`core/src/tank.rs:167`), то есть `shape.half_h * 2.0`. Число обязано
  быть одно на обе стороны — вынести в общее место, а не дублировать
  литералом.
- Зеркало стражей прогона (`resolve_world`, блок `for run in &blocks`) и
  контакты с предсказанными телами (`obb_vs_obb` по парам) переводятся на
  ту же функцию с зазором — иначе стражи начнут работать иначе, чем стены.

Риск: `SOLVER_ITERATIONS = 4` (:48) подбирался под текущий порядок. Если
после перестановки появятся дрожание или залипание в углах — менять число
итераций ПОСЛЕ того, как основной дефект закрыт, и фиксировать значение
тестом, а не на глаз.

Критерий этапа: тест `grazing_corner_hit_matches_the_host` из этапа 1
зелёный; `npm run sim:scenarios` — `bridge`, `crosslevel`, `fall` зелёные;
восемь ранее зелёных сценариев остались зелёными; паритет-тесты

## Этап 4. `terraces_climb`: своё расхождение по `x`/`vx`

Дефект отдельный: 24 нарушения из 198, `vx` Δ27.92 при пороге 25 и уровень
Δ0.15 при пороге 0.06 — то есть стороны расходятся не в одном кадре удара,
а систематически, на подъёме по крутому прогону `0 → 2`.

1. Диагностика по тесту из этапа 1 (или инструментацией сценария): в какой
   момент расходится — на входе на прогон, на смене уровня `z` через
   целое, на выезде?
2. Кандидаты, которые нужно проверить по порядку:
   - `level_state.grade(cos, sin)` в реплике против `LevelState` хоста:
     уклон под курсом считается из `RampSample::slope`, и обе стороны
     обязаны видеть одинаковый `level_height` (`MapConfig::level_height`
     едет в клиента в `set_map`);
   - момент щелчка уровня по ближайшему целому (`core/src/level.rs`,
     `state.z` → `state.level`) — если стороны щёлкают на разных шагах,
     маска столкновений и тяга расходятся на кадр;
   - тяга в горку: `motion::drive_accel(..., grade, model, &level_rules)`
     — общая формула, но входы (`throttle`, `forward_speed`) берутся из
     разных состояний.
3. Починка — там, где найдено расхождение; правило прежнее: одна формула
   на обе стороны, в общем месте (крейт или `crate::motion`), а не две

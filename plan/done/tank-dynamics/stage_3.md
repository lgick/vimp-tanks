## 3.3. Восстановление фазы полёта в реплике

`core/src/client/predictor.rs`.

Сегодня фаза падения восстанавливается обратной функцией по высоте
(`level::fall_elapsed`, `:604`). С баллистикой это невозможно: одной высоте
`z` соответствуют две фазы (подъём и снижение). Поэтому фаза приезжает
явно — вертикальной скоростью.

- `correct_level(&mut self, z: f32, level: u8)` (`:376`) →
  `correct_level(&mut self, z: f32, level: u8, vz: f32)`;
  `authoritative_level: Option<(f32, u8)>` → `Option<(f32, u8, f32)>`.
- `on_server_state` (`:587-612`) — блок `airborne`:

```rust
// в воздухе — если кадр говорит, что вертикальная скорость ненулевая,
// либо танк ниже своего уровня без опоры под ним. Первое условие важно
// для ПРЫЖКА: на взлёте z ещё равен уровню отрыва, и по высоте полёт
// неотличим от езды
let airborne = self.authoritative_level.filter(|&(z, level, vz)| {
    !on_ramp && (vz != 0.0 || (level >= 1 && z < level as f32 && !has_floor(level)))
});

if let Some((z, level, vz)) = airborne {
    let to = /* landing_level, как сейчас */;

    self.level_state.level = level;
    self.level_state.z = z;
    self.level_state.transit = Transit::Airborne {
        vz,
        from: level,
        to,
        // вершину дуги кадр не везёт: она нужна только урону, а урон
        // считает хост. Реплике достаточно не занижать её
        peak: z.max(level as f32),
    };
    self.level_state.clear_walls =
        z >= level as f32 + self.level_rules.jump_clearance;
}
```

- Наклон: после реконсиляции присвоить `self.pitch`/`self.roll`
  авторитетные значения из кадра? **Нет.** Наклон — производная от
  `slope_vec`/`vz`, которые реплика считает сама, и подстановка авторитета
  давала бы рывок раз в кадр. Наклон реплика доигрывает сама (этап 2), из
  кадра он нужен только чужим танкам.

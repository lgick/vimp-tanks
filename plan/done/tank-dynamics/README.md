# План: динамика танка (прыжок, приземление, наклон, дым)

## Зачем

Сейчас перемещение танка между уровнями 2.5D — скриптовое и «плоское»:

- **Падение не физическое.** `Transit::Falling { elapsed, from, to }`
  (`core/src/level.rs:33`) проигрывает линейный `lerp` по высоте за
  фиксированное время `fallTime * (from - to)` (`FallModel::z_at`,
  `vimp-engine-core-0.15.0/src/map.rs:1217`). Скорость на срыве ни на что не
  влияет: танк, вылетевший с рампы на полном газу, и танк, сползший с края
  пешком, летят одинаково. Прыжка нет вовсе — верхний торец рампы просто
  переводит танк на плоскую клетку.
- **Приземление не читается.** Единственный отклик — урон
  (`TanksSim::apply_fall_damage`, `core/src/tanks.rs:890`). Визуально танк
  просто «встаёт» на плиту.
- **Корпус не наклоняется.** Наклон был и его убрали: уклон восстанавливался
  на клиенте из разницы высот между кадрами и замирал у стоящего танка
  (`docs/ru/gameplay.md:139`, `docs/en/gameplay.md:141`). Данные об уклоне
  (`LevelState::slope_vec`, `core/src/level.rs:52`) на хосте есть, но в кадр
  не едут, поэтому чужие танки наклонить нечем.
- **Газ не дымит.** `Smoke.js` эмитит только по `condition` (степень
  повреждения). Нагрузка двигателя `engineLoad` (0 — холостой, 1 — полный
  ход, >1 — упор в стену) используется лишь для звука (`Tank.js`,
  `calculateEngineSoundParams`) и для следов гусениц (`Tracks.js`,
  `if (this._engineLoad > 1.0)`).

Итог: любое вертикальное перемещение выглядит одинаково и не зависит от
характера движения.

## Что делаем

1. **Баллистика вместо скрипта.** `Transit::Falling` заменяется на
   `Transit::Airborne { vz, from, to }` с интегрированием
   `vz -= g·dt; z += vz·dt`. Гравитация выводится из существующего
   `fallTime`, поэтому обычное падение с обрыва по времени и урону остаётся
   прежним. Вылет с верхнего торца рампы даёт стартовое `vz`,
   пропорциональное уклону и скорости, — это и есть прыжок.
2. **Наклон корпуса — авторитетный.** Хост считает `pitch`/`roll` из
   `slope_vec` и `vz` и везёт их в кадре, а не восстанавливает клиент из
   разницы высот. Это ровно та причина, по которой наклон убирали.
3. **Клиент рисует объём.** Корпус/пушка/остов становятся `PerspectiveMesh`
   и деформируются по `pitch`/`roll`; приземление даёт просадку (squash),
   пыль и звук.
4. **Дым от газа.** Выхлоп пропорционален `engineLoad`, буксование — отдельный
   выброс пыли из-под гусениц при `engineLoad > 1.0`. Всё масштабируется
   размером танка (`M1_SIZE`).

## Решения, принятые до начала работ

| Вопрос | Решение |
| --- | --- |
| Где живёт механика | Прыжок/полёт/приземление — **в Rust-ядре**, авторитетно. Анимация, дым, тени, тряска — на клиенте. |
| Управление в воздухе | Газ и поворот корпуса заблокированы (как сейчас), **башня работает** (это изменение: сегодня `input_locked` глушит и башню). |
| Столкновения в воздухе | Пока `z` выше уровня взлёта на `jumpClearance` — маска пустая (перелёт через стены). Ниже — прежняя `STATIC_LEVEL_GROUP`, иначе танк приземлится внутри здания. |
| Урон | Формула прежняя (`fallDamage` за уровень, кап `maxFallDamage`), но высота считается **от вершины дуги**, а не от уровня взлёта. |
| Наклон в 2D | `PerspectiveMesh` (PixiJS v8), углы квада считает чистая функция в `src/client/tilt.js`. |

## Инварианты, которые нельзя нарушить

1. **Хост и реплика — одни и те же функции.** Формулы живут в
   `core/src/motion.rs` и `core/src/level.rs`; `Tank::update`
   (`core/src/tank.rs:398`) и `Predictor::step_inner`
   (`core/src/client/predictor.rs:724`) зовут их **в одном и том же порядке**.
   Паритет проверяет тестовый модуль внутри `predictor.rs`
   (`replay_matches_continuous_simulation` и соседи).
2. **Порядок полей кадра позиционный.** `TankRow::fields()`
   (`core/src/tank.rs:30`), `src/config/snapshot.js` (`m1.fields`),
   `src/client/snapshotFields.js`, `TANK_FIELD_*` в
   `core/src/client/mod.rs:120-124` и `core/src/client/shot.rs:30-35`,
   хвост `render_overlay` (`core/src/client/mod.rs:378`) и
   `remote_tanks.rs` — шесть копий одного порядка. Расхождение молчит.
3. **`PLAYER_STATE_LEN = 8` менять нельзя** — константа движкового крейта
   (`vimp-engine-core-0.15.0/src/config.rs:284`). Вертикальное состояние
   идёт **не** через массив предсказания, а через тот же канал, что
   `z`/`level`: сырой кадр → `Predictor::correct_level`.
4. **Одноуровневая карта не должна заметить изменений.** Все новые формулы
   при `slope_vec == [0,0]` и `Transit::Grounded` обязаны совпадать со
   старыми бит-в-бит (тот же приём, что у `grade` в `motion::drive_accel`).
5. **Никаких коммитов.** Работа остаётся в рабочем дереве.

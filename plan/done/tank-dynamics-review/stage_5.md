# Этап 5. Клиент: объём танка — экструзия корпуса и светотень ✅ выполнен

Закрывает проблему 1: «танку не хватает объёма, картинка плоская, особенно
видно, когда танк заезжает на горку».

## Диагноз

Наклон, сделанный исходной задачей, честный: ядро считает `pitch`/`roll` и
везёт их в кадре, `src/client/tilt.js::tiltCorners` разворачивает квад
спрайта по двум осям и проецирует его той же формулой высоты, что и весь
2.5D. Но деформируется **плоский квад вида сверху**, у которого нет ни
боковых граней, ни толщины. Максимум, что даёт такая деформация, —
укорочение силуэта на `1 − cos(pitch)` (при `tiltMax = 0.6` рад это 17 %)
плюс экранный подъём `tilt.lift`. Глаз читает это как «спрайт слегка
сплющило», а не как «танк задрал нос»: не хватает того, что выдаёт объём в
этом проекте у всего остального, — **боковой грани и её затемнения**.

Карта этот приём уже использует:
`src/client/parts/map/extrusion.js::buildVolumeSlices` рисует блок здания
как `volume.slices` копий одной запечённой картинки, каждая сдвинута
сильнее предыдущей по `k = (level + volume·i/count) · shear`, и все, кроме
верхней, покрашены `volume.sideTint`. Танк — единственный объёмный объект
сцены, который этим приёмом не пользуется.

Второй недостающий признак — **светотень**: на горке у наклонённого
корпуса обязана темнеть уходящая вниз половина. Сейчас `tint` танка
занимает `levelView.tintFor(level)` (затемнение нижних ярусов), и
множителя наклона у него нет.

Побочный дефект того же кода: `tiltCorners` берёт `shear` параметром, а
`lift` — импортом `../config/render.js`. Функция объявлена чистой («должна
быть проверяемой без PixiJS»), но половину своих чисел берёт из
глобального модуля: тест не может проверить поведение при другом `lift`,
не перемокав модуль конфига.

## Решение

Три независимые правки; порядок любой, но 5.1 удобно делать первой.

### 5.1. `tiltCorners` получает `lift` параметром

`src/client/tilt.js`:

- убрать `import { tilt as tiltConfig } from '../config/render.js';`;
- добавить в деструктуризацию аргумента `lift` с описанием в JSDoc:

```js
 * @param {number} p.lift   экранный подъём поднявшегося края, доля высоты
```

- в теле заменить `tiltConfig.lift` на `lift`.

`src/client/parts/Tank.js::_setCorners` передаёт `lift: tiltConfig.lift`
рядом с `shear: parallaxConfig.shear`. Конфиг читает парт — как и весь
остальной 2.5D.

`tests/client/tilt.test.js`: во всех существующих вызовах добавить
`lift`. Добавить тест «`lift = 0` оставляет наклон чистым сжатием»
(проверяет, что подъём — отдельное слагаемое, а не часть проекции).

### 5.2. Экструзия корпуса

**Конфиг** — `src/config/render.js`, блок `tilt`, новые поля:

```js
  // толщина корпуса в УРОВНЯХ: столько же «высоты», сколько у объёмов
  // карты (`volume`), и та же проекция. 0 выключает экструзию
  body: 0.22,

  // число срезов боковой грани. Смысл и цена те же, что у `volume.slices`
  // (K лишних вызовов отрисовки на танк), но у танка их три меша, а не
  // один слой, поэтому число своё и меньше
  bodySlices: 3,

  // затемнение боковой грани корпуса; `volume.sideTint` — её родня, но
  // танк тонируется ещё и уровнем (`levelView.tintFor`), поэтому тинт
  // задаётся своим числом
  sideTint: 0x8c919b,
```

**Парт** — `src/client/parts/Tank.js`.

Танк уже строит три `PerspectiveMesh` (`body`, `gun`, `wreck`) фабрикой
`mesh()`. Экструзия добавляет под КАЖДЫЙ из них `tilt.bodySlices` копий
того же меша:

```js
    // боковая грань корпуса: K копий той же текстуры, каждая ниже
    // предыдущей по высоте и потому смещённая к центру камеры слабее.
    // Тот же приём, которым карта строит объёмы зданий
    // (`src/client/parts/map/extrusion.js::buildVolumeSlices`): экструзия
    // одной картинки вместо второй текстуры «вид сбоку». Срезы уходят
    // ПОД сам меш, поэтому добавляются в контейнер первыми
    this._slices = [];
```

В конструкторе, до `this.addChild(this.body, this.gun, this.wreck)`:

```js
    for (let i = 0; i < tiltConfig.bodySlices; i += 1) {
      const slice = mesh();

      slice.tint = tiltConfig.sideTint;
      this._slices.push(slice);
      this.addChild(slice);
    }
```

Срезы строятся только для КОРПУСА и ОСТОВА — у пушки своя высота и
собственный поворот, её объём читается уже тем, что она лежит поверх
корпуса. Значит у каждого среза есть «хозяин»: живой корпус или остов.
Проще всего держать по одному набору срезов и переназначать им текстуру
вместе с `create()`:

- в `create()`, в ветке «уничтожен»: всем срезам `texture` остова,
  `visible = true`;
- в ветке «жив»: текстура корпуса;
- при `condition === 0 && !this._textures.destroyed` — `visible = false`.

**Геометрия среза.** Срез `i` (нумерация с 1) лежит на высоте
`z − body·(count − i)/count`, то есть ниже корпуса. Смещение относительно
корпуса, который уже стоит в `offsetPoint(world, cam, z·shear)`:

```
Δ = (мировая точка − центр камеры) · (k_i − k_body)
```

где `k_i = (z − body·(count − i)/count) · shear`, `k_body = z · shear`.
Разность отрицательна, значит срез уезжает К центру камеры — ровно как
нижние срезы здания.

В `_applyTilt` добавить (после расчёта `size`/`squashY`):

```js
    const count = this._slices.length;

    for (let i = 0; i < count; i += 1) {
      // высота среза: нижний — на всю толщину корпуса ниже верхней грани
      const depth = (tiltConfig.body * (count - i)) / count;

      // те же углы, что у корпуса, но масштаб — свой: срез лежит НИЖЕ, а
      // в этой проекции всё, что ниже, мельче (`1 + z·shear`)
      const sliceScale = 1 + (this._z - depth) * parallaxConfig.shear;

      this._setCorners(
        this._slices[i],
        this._bodyAnchor,
        0,
        this._scaleFactor * sliceScale,
        squashY,
      );
    }
```

А экранное смещение срезов считается там же, где смещается сам танк, — в
`_updateView`, потому что ему нужен центр камеры:

```js
    // срезы боковой грани: каждый лежит ниже корпуса и потому смещён к
    // центру камеры слабее. Смещение локальное — сам контейнер уже стоит
    // в проекции высоты корпуса
    const count = this._slices.length;

    for (let i = 0; i < count; i += 1) {
      const depth = (tiltConfig.body * (count - i)) / count;
      const dk = -depth * parallaxConfig.shear;

      this._slices[i].position.set(
        (this._worldX - camera.x) * dk,
        (this._worldY - camera.y) * dk,
      );
    }
```

`camera` может быть `null` (парт ещё не на сцене) — в этом случае
`offsetPoint` уже возвращает исходную точку, и срезам надо ставить
`position.set(0, 0)`. Предусмотреть.

**Выключение.** `tilt.body === 0` или `tilt.bodySlices === 0` ⇒ срезы не
создаются вовсе, и парт работает ровно как до этапа. Это путь отхода, он
же — режим для слабых машин.

### 5.3. Светотень по наклону

Корпус, наклонённый носом вверх, обязан ловить больше света передней
гранью и меньше — задней. В плоской проекции дешёвая имитация —
**скалярный множитель тинта** по проекции нормали корпуса на фиксированное
направление света.

`src/config/render.js`, блок `tilt`:

```js
  // светотень наклона: во сколько раз меняется яркость корпуса на
  // предельном наклоне. 0 — света нет, картинка как до этапа
  shading: 0.28,

  // направление света в СИСТЕМЕ ЭКРАНА (не корпуса): [x, y], нормируется
  // при чтении. По умолчанию свет с северо-запада — так же освещены
  // боковые грани зданий
  lightDir: [-0.7, -0.7],
```

Новая чистая функция в `src/client/tilt.js`:

```js
/**
 * Множитель яркости корпуса по его наклону. Наклон поворачивает нормаль
 * корпуса; её проекция на направление света и есть яркость. Функция
 * чистая и не знает про PixiJS — числа приходят параметрами.
 *
 * @param {object} p
 * @param {number} p.angle    курс корпуса, рад
 * @param {number} p.pitch    продольный наклон, рад
 * @param {number} p.roll     поперечный наклон, рад
 * @param {number[]} p.lightDir  направление света в экранных осях
 * @param {number} p.shading  глубина эффекта (0 — выключено)
 * @returns {number} множитель яркости, около 1.0
 */
export function tiltShade({ angle, pitch, roll, lightDir, shading }) {
  if (!shading) {
    return 1;
  }

  // наклон корпуса = поворот его нормали. Малые углы: наклон вокруг
  // локального X даёт составляющую вдоль курса, вокруг Y — поперёк
  const cos = Math.cos(angle);
  const sin = Math.sin(angle);

  // нормаль в экранных осях (её вертикальная составляющая нам не нужна:
  // свет задан в плоскости экрана)
  const nx = -Math.sin(pitch) * cos - Math.sin(roll) * sin;
  const ny = -Math.sin(pitch) * sin + Math.sin(roll) * cos;

  const len = Math.hypot(lightDir[0], lightDir[1]) || 1;
  const dot = (nx * lightDir[0] + ny * lightDir[1]) / len;

  return 1 + dot * shading;
}
```

В `Tank.js`, в `_updateView`, ПОСЛЕ того как `levelView` записал
`this.tint`:

```js
    // светотень наклона поверх тинта уровня: множитель, а не замена —
    // затемнение нижних ярусов обязано остаться
    if (tiltConfig.enabled && tiltConfig.shading) {
      const shade = clamp(
        tiltShade({
          angle: this.rotation,
          pitch: this._pitch,
          roll: this._roll,
          lightDir: tiltConfig.lightDir,
          shading: tiltConfig.shading,
        }),
        0.5,
        1.5,
      );

      this.tint = scaleTint(this.tint, shade);
    }
```

`scaleTint` — маленький помощник рядом с `tiltShade` в `tilt.js`
(разложить `0xRRGGBB` на три канала, умножить каждый, зажать в 0…255,
собрать обратно). Он же покрывается тестами.

`clamp` уже импортирован в `Tank.js` из `vimp-engine/lib/math.js`.

## Тесты

**`tests/client/tilt.test.js`** — дополнить:

1. `lift` параметром (см. 5.1) и тест `lift = 0`;
2. `tiltShade`: ровный танк (`pitch = roll = 0`) даёт ровно `1`;
3. `tiltShade`: `shading = 0` даёт `1` при любом наклоне;
4. `tiltShade`: наклон НАВСТРЕЧУ свету и ОТ света дают множители по разные
   стороны от 1, симметричные по модулю;
5. `tiltShade`: результат зависит от `angle` — один и тот же `pitch` у
   танка, повёрнутого на 180°, даёт зеркальный множитель;
6. `scaleTint`: `0xffffff × 0.5 → 0x808080` (с точностью до округления),
   `× 2` не выходит за `0xffffff`, `0x000000` остаётся нулём.

**`tests/client/parts/Tank.test.js`**:

7. `корпус получает срезы боковой грани`: после конструктора
   `tank.children` содержит `tilt.bodySlices` мешей с тинтом
   `tilt.sideTint`, и они лежат в списке ДО `tank.body` (порядок = порядок
   отрисовки);
8. `срезы смещены к центру камеры`: при камере, смещённой по `x`, у
   нижнего среза `position.x` по модулю больше, чем у верхнего, и знак
   противоположен смещению корпуса;
9. `tilt.body = 0 выключает экструзию`: с обнулённым конфигом срезов нет
   (мокать модуль конфига так же, как это делают существующие тесты
   `tilt.enabled`);
10. `срезы берут текстуру остова у уничтоженного танка`.

## Проверка этапа

```bash
npx eslint . && npm test && npm run build
```

Ручная — главная проверка этого этапа: `VITE_MAP='terraces' npm run dev`,
въехать на крутую рампу и постоять на ней. Танк обязан читаться как
коробка с высотой: видна боковая грань, уходящая вниз половина темнее.
Проехать по ровной земле — картинка обязана остаться прежней (на
`slope_vec == [0,0]` и `pitch == roll == 0` и экструзия, и светотень
вырождаются в прежний спрайт плюс ровную «юбку»).

## Цена

`bodySlices = 3` добавляет 3 меша на танк (не 9: срезы строятся под
корпус/остов, пушка своих не получает). При 8 танках — 24 лишних меша со
своей геометрией. Это тот же порядок, что у `volume.slices = 4` на слой
карты. Если на слабой машине станет тяжело, путь отхода —
`tilt.bodySlices: 1` или `tilt.body: 0`.

# Этап 6. Приземление: тряска, просадка, пыль и кросс-тест порогов ✅ выполнен

Закрывает проблему 5 («уменьши тряску при падении») и хвост проблемы 2
(приземление обязано читаться, но не оглушать). Требует этапа 1 (дуга
прыжка стала другой, и пороги считаются от неё) и этапа 3 (детектор
касания теперь один и работает у чужих танков).

## Диагноз

Приземление считается в двух местах с ЧЕТЫРЬМЯ числами, из которых два
продублированы:

| Что | Где | Числа |
| --- | --- | --- |
| тряска камеры (авторитетно, ядро) | `src/config/game.js` → `coreParams.levels.landingShake` | `intensity 6`, `duration 300`, `minImpact 1.5`, `fullImpact 6` |
| просадка корпуса, пыль, звук (клиент) | `src/config/render.js` → `landing` | `squash 0.22`, `duration 260`, `minImpact 1.5`, `fullImpact 6` |

`minImpact`/`fullImpact` обязаны совпадать — иначе камера тряхнётся без
пыли или наоборот. Связаны они СЕЙЧАС только перекрёстными комментариями
в обоих файлах. Это ровно тот класс расхождений, который в этом проекте
принято закрывать тестом (как `tests/config/snapshot.test.js` закрывает
позиционный контракт кадра).

Сама тряска до этапа 1 всегда была на потолке: `impact` касания после
прыжка с `rampSteep` равен 9.21 при `fullImpact = 6` ⇒ коэффициент
`k = clamp((9.21 − 1.5)/4.5) = 1`, интенсивность полная, и так на КАЖДОМ
прыжке. После этапа 1 `impact` прыжка ≈ 3.22 ⇒ `k = 0.38`, но и этого
многовато: жалоба была на силу тряски как таковую.

Опорные значения после этапа 1 (`g = 16.33`):

| Событие | `impact`, уровней/с | `k` при `min 1.5`, `full 6` |
| --- | --- | --- |
| прыжок с крутой рампы | 3.22 | 0.38 |
| падение с одного уровня | 5.72 | 0.94 |
| падение с двух уровней | 8.08 | 1.0 (потолок) |

Шкала попадает в диапазон правильно — менять надо только интенсивность и
глубину просадки.

## Решение

### 6.1. Настройка `src/config/game.js`

```js
      landingShake: {
        // при полном ударе, единицы как у оружия. 6 читалось как удар по
        // экрану на каждом прыжке; падение с уровня даёт k ≈ 0.94, то
        // есть почти всю интенсивность, поэтому число задаёт силу именно
        // ПАДЕНИЯ, а не прыжка
        intensity: 3,
        duration: 220, // мс
        minImpact: 1.5, // ниже — мягкое касание, тряски нет
        fullImpact: 6, // уровней/с, дающие полную интенсивность
      },
```

`intensity 6 → 3`, `duration 300 → 220`. Пороги не трогаем: они
согласованы с дугой этапа 1 (прыжок даёт `k ≈ 0.38`, падение — почти 1).

### 6.2. Настройка `src/config/render.js`

```js
export const landing = {
  // вертикальная скорость касания (уровней/с), дающая полную просадку
  fullImpact: 6,

  // максимальное сжатие корпуса по вертикали (доля). 0.22 на каждом
  // прыжке читалось как «танк складывается»; просадка обязана быть
  // заметной, но не менять силуэт
  squash: 0.14,

  // длительность просадки и возврата, мс
  duration: 260,

  // порог |vz| касания, ниже которого приземление считается мягким:
  // ни просадки, ни пыли, ни звука
  minImpact: 1.5,
};
```

### 6.3. Кросс-тест порогов вместо комментария

Новый файл `tests/config/landing.test.js`:

```js
import { describe, it, expect } from 'vitest';
import gameConfig from '../../src/config/game.js';
import { landing } from '../../src/config/render.js';

// Приземление считается в ДВУХ местах: тряску камеры считает ядро по
// coreParams.levels.landingShake (WASM), просадку/пыль/звук — клиентский
// рендер по `landing`. Общего источника у них нет (движок конфига партам
// не отдаёт), поэтому пороги обязаны совпадать численно — иначе камера
// тряхнётся без пыли или наоборот. До этого теста связь держалась на
// перекрёстных комментариях в обоих файлах.
describe('пороги приземления: game.js ↔ render.js', () => {
  const shake = gameConfig.coreParams.levels.landingShake;

  it('minImpact совпадает', () => {
    expect(shake.minImpact).toBe(landing.minImpact);
  });

  it('fullImpact совпадает', () => {
    expect(shake.fullImpact).toBe(landing.fullImpact);
  });

  it('шкала не вырождена', () => {
    expect(shake.fullImpact).toBeGreaterThan(shake.minImpact);
  });
});
```

Если `landingShake` в `game.js` когда-нибудь станет необязательным
(сейчас блок есть), тест обязан пропускаться, а не падать: обернуть в
`it.skipIf(!shake)`. Сейчас блок присутствует — писать просто.

### 6.4. Проверить, что тряска не двоится

`TanksSim::push_landing_shake` (`core/src/tanks.rs:908`) кладёт
`CoreEvent::Shake` на КАЖДОЕ `LevelEvent::Landed`. Реплика
(`Predictor`) событий не собирает — это проверено при исходной задаче и
записано в её `stage_7.md`. Перед сдачей этапа перепроверить, что это всё
ещё так:

```
grep -n "Landed" core/src/client/predictor.rs
```

Ожидаемо: ни одного места, где событие приземления реплики уходило бы в
`ctx.events`. Если появилось — тряска будет двойной, и это надо чинить до
настройки интенсивности.

### 6.5. Пыль приземления

`DUST_CONFIG.landingBurst = 8` частиц на каждую из двух точек контакта —
до 16 частиц на приземление. Число подбиралось под `impact`, всегда
равный 1. Теперь прыжок даёт `impact ≈ 0.38` ⇒ `Math.round(8 × 0.38) = 3`
частицы на точку. Это мало, всплеск пропадёт.

Ничего не меняя в формуле, поднять `landingBurst` до `14`: прыжок даст
5 частиц на точку, падение с уровня — 13. Правка в
`src/client/parts/Dust.js`, `DUST_CONFIG`:

```js
  // приземление: частиц на каждую точку контакта при полном ударе. Число
  // считается от силы удара (`landingBurst × impact`), а мягкое касание
  // (impact = 0) не даёт ни одной — порог живёт в `landing.minImpact`
  landingBurst: 14,
```

## Тесты

**`core/tests/sim.rs`** — существующие четыре теста тряски
(«жёсткое касание = ровно одно `Shake`», «мягкое = ничего», «интенсивность
зажата потолком», «без блока в конфиге событий нет») продолжают работать
и правок не требуют: они написаны на своих правилах, а не на числах
`game.js`. Убедиться, что это так; если какой-то из них зашит на
`intensity = 6` — переписать на относительное утверждение.

**Новый тест в `core/tests/sim.rs`**:
`a_ramp_jump_shakes_the_camera_less_than_a_fall` — прыжок с рампы и
падение с уровня в одном тесте, сравнение `intensity` двух событий
`Shake`. Он закрепляет главное свойство настройки: прыжок тише падения.

**`tests/config/landing.test.js`** — см. 6.3.

**`tests/client/parts/Dust.test.js`** — существующий тест всплеска: если
он зашит на конкретное число частиц, перевести его на
`DUST_CONFIG.landingBurst`, иначе правка 6.5 его уронит.

# Этап 7. Карта `overpass`, документация и CHANGELOG ✅ выполнен

Последний этап: добивает проблему 3 со стороны карты, закрепляет её
регрессионным тестом и приводит документацию в соответствие со всем, что

## 7.1. Что от проблемы 3 остаётся после этапа 1

Этап 1 закрывает главное: `maxLaunchVz 3.5` ограничивает дугу 0.375
уровня, `jumpClearance 0.45` лежит выше неё, значит `clear_walls` при
штатной настройке **не включается никогда** — маска коллизий в полёте
всегда `STATIC_LEVEL_GROUP`, и танк видит и перила, и периметр карты.
Улететь с карты он больше не может.

Остаётся вторая половина жалобы: на `overpass` танк, влетающий на мост,
всё равно упирается в дальние перила, потому что проезжая часть — **три
тайла** (`y` 28…30), а горизонт даже укороченного прыжка ≈ 6 тайлов. Танк
не вылетит за карту, но приземление будет ударом в перила. Карта не даёт
прыжку места.

## 7.2. Правка `src/data/maps/overpass.js`

Расширить проезжую часть с трёх рядов до **пяти**, сдвинув северный борт
на два тайла к северу. Южный борт и северная рампа остаются на месте —
именно они несут первую точку респауна `team1` и сценарий `bridge.json`.

Изменения в объекте `bridge` (строки 21–29):

```js
// геометрия эстакады: 5 тайлов проезжей плиты (26..30) плюс перила
// по обеим длинным сторонам (25 и 31). Пять, а не три: горизонт прыжка с
// рампы — около шести тайлов (см. plan/tank-dynamics-review/stage_1.md),
// и на трёхтайловой плите любой прыжок кончался ударом в дальние перила
const bridge = {
  railNorth: 25,
  slabTop: 26,
  slabBottom: 30,
  railSouth: 31,
  left: 2, // внутренняя кромка периметральной стены
  right: width - 3,
};
```

Южная рампа (`rampSouth`, поднимается на юг, стоит СЕВЕРНЕЕ моста) теперь
налезает на плиту: её `y0..y1 = 24..26` пересекается с новым `slabTop`.
Сдвинуть её на два тайла к северу (строка 35):

```js
const rampSouth = { x0: 74, x1: 76, y0: 22, y1: 24 };
```

Верхний торец рампы (`y = 24`) остаётся вплотную к северному борту
(`railNorth = 25`), в котором напротив её колонок уже открыт проём —
логика `openNorth` считает проём по `rampSouth.x0..x1` и правки не
требует.

Северная рампа (`rampNorth`, `y0..y1 = 32..34`) не трогается: её торец
вплотную к `railSouth = 31`, проём в нём считается по её колонкам.

**Что ещё придётся поправить в том же файле:**

- Комментарий у `physicsDynamic` («Средний ряд плиты (29) свободен — по
  нему идут отладочные сценарии») — средний ряд теперь 28, но ряд 29
  по-прежнему плита и по-прежнему свободен. Переписать на «Ряд 29 плиты
  свободен».
- Ящики моста объявлены через `bridge.slabTop`/`bridge.slabBottom` и
  уезжают за бортами сами — правок не требуют.
- Точки респауна на плите (`spawnOn(10, 29, 0, 1)`, `spawnOn(16, 29, 0, 1)`)
  попадают в новые 26…30 — правок не требуют.
- Шапка файла (строки 1–4) описывает мост; обновить «3 тайла проезжей
  плиты» на «5 тайлов».

## 7.3. Регрессионный тест «прыжок не выпускает с карты»

Новый тест в `core/tests/sim.rs` рядом с
`terraces_ramp_launches_the_tank`:

```rust
#[test]
fn a_jump_never_leaves_the_map() {
    // Главная защита проблемы 3: пока дуга ниже `jumpClearance`, маска в
    // полёте остаётся STATIC_LEVEL_GROUP, и периметр карты держит танк.
    // Тест ловит любую настройку, при которой это перестаёт быть правдой
    // (maxLaunchVz вверх, jumpClearance вниз, fallTime вниз).
}
```

Содержание: `overpass`, спавн у подножия северной рампы (первая точка
`team1`), полный газ, 900 шагов. На каждом шаге проверять, что позиция
танка лежит внутри карты с запасом в один тайл, и что
`state.clear_walls` не был `true`. Границы карты берутся из тех же
`width`/`height`/`step`/`scale`, что и в `overpass.js`, — в тестовом
модуле уже есть помощник для клетки `terraces` (`terraces_cell`), сделать
такой же `overpass_cell`/`overpass_bounds` рядом.

Второй тест — `a_jump_lands_on_the_bridge`: тот же прогон, после
приземления `level_of(&core, 1) == 1` (танк на плите, а не отлетел вниз).
Он же и есть проверка правки 7.2: на трёхтайловой плите он бы падал.

## 7.6. CHANGELOG

`CHANGELOG.md`, раздел `## [Unreleased]`. Записи (английский, Keep a
Changelog):

**`### ⚠️ Breaking`**
- `levels.fallDamage` теперь цена за уровень СВЕРХ `fallDamageFreeHeight`,
  а не за уровень падения. Конфиги игр, переопределяющие блок `levels`,
  обязаны пересчитать значение.

**`### Migration`**
- Чтобы сохранить прежнюю цену падения ровно с одного уровня, задать
  `fallDamage` вдвое больше прежнего при `fallDamageFreeHeight: 0.5`
  (в этом репозитории 15 → 30). Падение с двух уровней при этом дорожает
  с 30 до 45 HP — регулируется `maxFallDamage`.

**`### Added`**
- `levels.maxLaunchVz` — потолок вертикальной скорости вылета с рампы.
- `levels.fallDamageFreeHeight` — мёртвая зона урона падения.
- `tilt.body`/`tilt.bodySlices`/`tilt.sideTint` — экструзия корпуса.
- `tilt.shading`/`tilt.lightDir` — светотень наклона.
- `src/client/landing.js` — общий детектор касания.
- Валидация блока `levels.landingShake`.
- Сценарий `tests/scenarios/overpass_jump.json`.

**`### Changed`**
- Тень танка рисуется на опоре, а не в мировой точке: у стоящего танка она
  под корпусом, разъезд показывает подъём над опорой.
- `vz` в схеме снапшота больше не интерполируется (`discrete`).
- Настройка прыжка и приземления: `rampLaunchFactor` 1.0 → 0.35,
  `jumpClearance` 0.2 → 0.45, `landingShake.intensity` 6 → 3,
  `landingShake.duration` 300 → 220, `landing.squash` 0.22 → 0.14.
- `overpass`: проезжая часть моста расширена с трёх тайлов до пяти,
  южная рампа сдвинута на два тайла к северу.

**`### Fixed`**
- Приземление ЧУЖИХ танков не давало ни просадки, ни пыли, ни звука:
  детектор требовал точного нуля у интерполированной `vz`.
- Прыжок с крутой рампы отнимал здоровье и позволял вылететь за пределы
  карты.

**`### Removed`**
- `level::fall_speed_at` — потребителей не осталось после того, как `vz`
  поехала в кадре.

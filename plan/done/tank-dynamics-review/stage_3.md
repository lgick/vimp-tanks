# Этап 3. Кадр: `vz` перестаёт интерполироваться, детектор касания — один ✅ выполнен

Этот этап чинит дефект, которого в списке ручного тестирования не было, но
который прямо бьёт по проблемам 2 и 5: **у чужих танков приземление почти
никогда не детектируется**, поэтому пыль, просадка корпуса и звук
`tankLanding` у других игроков теряются, а у своего срабатывают всегда.
Разное поведение своего и чужого танка легко списать на «так и задумано»,
поэтому чинить надо до настройки приземления (этап 6).

## Диагноз

### 3.1. `vz` объявлен интерполируемым

`src/config/snapshot.js:50`:

```js
      { name: 'vz', ty: 'f32', interp: 'lerp' },
```

Движок интерполирует строки чужих танков между кадрами
(`packages/engine/core/src/client/interpolator.rs`, `interpolate_row` →
`Interp::Lerp`). Значит `vz` у чужого танка приходит в парт СГЛАЖЕННЫМ.

Детектор касания (`src/client/parts/Tank.js`, `update`):

```js
    if (this._prevVz < -landingConfig.minImpact && this._vz === 0) {
```

требует двух вещей одновременно:

1. **`this._vz === 0` — точное равенство нулю** у величины, полученной
   `lerp(a, b, alpha)`. Ноль отдаётся ровно при `alpha === 1`, то есть
   только если рендер-тик попал ровно в границу кадров. Обычно не попадает.
2. **`this._prevVz < -1.5`** — но предыдущая выборка тоже сглажена и уже
   подтянута к нулю. Даже когда условие 1 случайно выполняется, условие 2
   к этому моменту часто уже нарушено.

У СВОЕГО танка проблемы нет: его строка приходит из
`RemoteTanks::render_data` / `render_overlay`, то есть из сырого
предсказанного состояния без интерполяции, и `vz` честно щёлкает
`3.22 → 0`.

Итог: просадка, пыль и звук приземления — привилегия локального игрока.
Тесты этого не ловят, потому что в `tests/client/parts/Tank.test.js` и
`Dust.test.js` строки подаются вручную, сразу с `vz = 0`.

### 3.2. Детектор скопирован дословно

`src/client/parts/Tank.js` (`update`) и `src/client/parts/Dust.js`
(`update`) содержат одно и то же выражение с одними и теми же двумя
константами и одной и той же формулой силы удара:

```js
this._prevVz < -landingConfig.minImpact && this._vz === 0
…
Math.min(1, -this._prevVz / landingConfig.fullImpact)
```

В `Dust.js` это даже отмечено комментарием «тот же детектор, что в
`Tank.js`». Два места, которые обязаны меняться синхронно и ничем не
связаны.

## Решение

### Шаг 3.1. `vz` → `interp: 'discrete'`

Движок поддерживает три режима (`Interp::Lerp`, `LerpAngle`, `Discrete`,
`packages/engine/core/src/config.rs:129`; документировано в
`vimp-engine/docs/en/network.md`). `discrete` отдаёт значение кадра `A`
без смешивания — то есть держит его до следующего кадра и щёлкает ровно на
границе.

`src/config/snapshot.js`, поле `vz`:

```js
      // НЕ интерполируется: `vz` — детектор касания, а не плавная
      // величина. `lerp` размазывал щелчок `vz → 0` по буферу
      // интерполяции, и приземление ЧУЖОГО танка (просадка, пыль, звук)
      // не детектировалось вовсе: условие `vz === 0` требует точного нуля,
      // а сглаженная выборка его почти никогда не даёт
      { name: 'vz', ty: 'f32', interp: 'discrete' },
```

`pitch` и `roll` остаются `lerp` — это плавные углы.

Обновить комментарий-предупреждение в шапке файла (строки 13–18): там
сказано «порядок и interp полей позиционно привязаны к Row-структурам». В
Rust `TankRow::fields()` кладёт `vz` как `FieldValue::F32` — тип не
меняется, менять на стороне Rust нечего, но в комментарии стоит явно
написать, что `vz` единственное поле `m1` с `discrete`, и почему.

`tests/config/snapshot.test.js` сверяет только ИМЕНА полей по индексам
(`nameOf`, плюс проверка хвоста `['z','level','vz','pitch','roll']`) —
правок он не требует, но в него надо дописать утверждение про режим, иначе
вернуть `lerp` можно будет молча:

```js
  // `vz` — детектор касания, а не плавная величина: сглаженная выборка
  // точного нуля не даёт, и приземление чужого танка перестаёт
  // детектироваться (см. src/client/landing.js)
  it('vz не интерполируется', () => {
    expect(snapshot.m1.fields[fields.M1_VZ].interp).toBe('discrete');
    expect(snapshot.m1.fields[fields.M1_PITCH].interp).toBe('lerp');
    expect(snapshot.m1.fields[fields.M1_ROLL].interp).toBe('lerp');
  });
```

### Шаг 3.2. Один детектор на обе части

Новый модуль `src/client/landing.js`:

```js
// Детектор касания земли по вертикальной скорости кадра. Общий для
// `Tank.js` (просадка корпуса) и `Dust.js` (всплеск пыли и звук): оба
// парта получают ОДНУ И ТУ ЖЕ строку снапшота, поэтому связывать их
// колбэком не нужно, а держать две копии правила — нельзя: разъедутся
// молча, и просадка окажется без пыли.
//
// `vz` в схеме снапшота объявлен `discrete` (`src/config/snapshot.js`)
// именно ради этого детектора: сглаженная выборка точного нуля не даёт.
import { landing as landingConfig } from '../config/render.js';

/**
 * Сила удара при касании, 0 — касания не было.
 *
 * @param {number} prevVz  вертикальная скорость прошлого кадра
 * @param {number} vz      вертикальная скорость этого кадра
 * @returns {number} 0..1 — доля от `landing.fullImpact`
 */
export function landingImpact(prevVz, vz) {
  // касание: снижение было заметным, а в этом кадре скорость обнулилась
  if (!(prevVz < -landingConfig.minImpact) || vz !== 0) {
    return 0;
  }

  return Math.min(1, -prevVz / landingConfig.fullImpact);
}
```

`!(prevVz < …)`, а не `prevVz >= …`: так `NaN` в строке (короткий ряд)
даёт `0`, а не исключение и не ложное срабатывание.

**`src/client/parts/Tank.js`**, `update` — заменить блок детектора на:

```js
    const impact = landingImpact(this._prevVz, this._vz);

    if (impact > 0) {
      this._landImpact = impact;
      this._landTimer = landingConfig.duration;
      this._onLanded?.(impact);
    }

    this._prevVz = this._vz;
```

**`src/client/parts/Dust.js`**, `update`:

```js
    const impact = landingImpact(this._prevVz, this._vz);

    if (impact > 0) {
      this._triggerLandingBurst(impact);
      this._playLandingSound(impact);
    }

    this._prevVz = this._vz;
```

Импорт `landing as landingConfig` в `Dust.js` после этого нужен только
если файл использует его ещё где-то — проверить и убрать лишний импорт
(иначе `eslint` укажет сам).

### Шаг 3.3. Тесты

**Новый `tests/client/landing.test.js`** (чистая функция, PixiJS не
нужен):

1. мягкое касание (`prevVz = -1.0`, `vz = 0`) при `minImpact 1.5` → `0`;
2. жёсткое касание (`prevVz = -6`, `vz = 0`) при `fullImpact 6` → `1`;
3. промежуточное (`prevVz = -3`, `vz = 0`) → `0.5`;
4. сильнее потолка (`prevVz = -20`) → ровно `1`, не больше;
5. полёт продолжается (`prevVz = -6`, `vz = -3`) → `0`;
6. взлёт (`prevVz = 4`, `vz = 0`) → `0`;
7. `NaN` в любом аргументе → `0`.

**`tests/client/parts/Tank.test.js`** и **`Dust.test.js`**: существующие
тесты приземления продолжают работать (форма вызова не изменилась).
Добавить по одному тесту «полёт не считается касанием»: два `update`
подряд с `vz = -6` и `vz = -3` не дают ни `_landTimer`, ни всплеска пыли.

**`tests/config/snapshot.test.js`**: утверждение про `discrete` у `vz`
(см. шаг 3.1).

## Оговорка для исполнителя

`discrete` сдвигает момент детекции на длину буфера интерполяции (по
умолчанию `interpolation.delay` движка, десятки мс) — но ровно так же
сдвинуты и позиция, и высота чужого танка, поэтому пыль появится в нужной
точке и в нужный момент относительно картинки. Задержки относительно
СВОЕГО танка тут нет: своя строка идёт мимо интерполятора.

# План: ревью и доводка задачи «динамика танка» (коммит 490062c)

## Откуда план

Кодревью задачи `plan/done/tank-dynamics/` (коммит `490062c`,
`tank-dynamics`) плюс разбор пяти проблем, найденных при ручном
тестировании. Базовое состояние дерева на момент ревью — **зелёное**:

```
npx eslint .              → 0
npm test                  → 37 файлов, 372 теста
npm run core:test         → 284 + 53 теста
npm run sim:scenarios     → 13 сценариев, all green
```

То есть ни одна из проблем ниже тестами не ловится: это дефекты настройки,
проекции и контракта кадра, а не сломанный код.

## Измерение, от которого пляшет вся первая половина плана

Во время ревью в `core/tests/sim.rs::terraces_ramp_launches_the_tank`
временно добавлялся вывод накопленного `peak` (дерево возвращено в
исходное состояние). Результат на карте `terraces`, крутой прогон
`rampSteep` (0 → 2, четыре клетки, уклон 0.5):

| Величина | Значение | Откуда |
| --- | --- | --- |
| `peak` дуги | **4.6** уровня | замер |
| уровень отрыва | 2 | замер |
| высота дуги | **2.6** уровня | `peak - from` |
| гравитация `g` | 16.33 уровней/с² | `2 / fallTime²`, `fallTime = 0.35` |
| `vz` отрыва | **9.21** уровней/с | `sqrt(2·g·2.6)` |
| время полёта | **1.13 с** | `2·vz/g` |
| горизонт полёта | ≈ 220 мировых единиц (≈ 17 тайлов) | `v_x · t`, `v_x ≈ 195` |
| урон приземления | **39 HP** | `fallDamage 15 × 2.6` |
| `impact` касания | 9.21 против `fullImpact 6` | тряска и просадка всегда на потолке |

Одно число — `rampLaunchFactor: 1.0` — порождает сразу проблемы 2, 3 и 5.

## Проблемы и куда они ушли

| № | Проблема из тестирования | Диагноз | Этап |
| --- | --- | --- | --- |
| 1 | Танку не хватает объёма, картинка плоская | Наклон деформирует ПЛОСКИЙ квад вида сверху; боковых граней и светотени нет | 5 |
| 2 | На горке подпрыгивает высоко и теряет HP | `rampLaunchFactor 1.0` даёт дугу 2.6 уровня; у урона падения нет мёртвой зоны | 1 |
| 3 | Перелетает забор и вылетает за пределы карты | Дуга 2.6 уровня держит `clear_walls` почти весь полёт, а `clear_walls` даёт **пустую** маску коллизий — пропадает и периметр карты | 1 + 7 |
| 4 | Тень уезжает от танка и живёт своей жизнью | Тень стоит в МИРОВОЙ точке, а корпус — в проекции `z·shear` от центра камеры: разъезд равен `z·shear·(расстояние до центра экрана)` | 4 |
| 5 | Сильная тряска при падении | `impact` всегда ≥ `fullImpact`, плюс сама интенсивность великовата | 6 |

Дефекты кодревью, которых в списке тестирования не было:

| Дефект | Этап |
| --- | --- |
| `vz` в схеме снапшота объявлен `interp: 'lerp'` — детектор касания `vz === 0` у ЧУЖИХ танков почти никогда не срабатывает: пыль, просадка и звук приземления у других игроков теряются | 3 |
| Детектор касания скопирован в `Tank.js` и `Dust.js` дословно | 3 |
| `LandingShake` не проходит `TanksConfig::validate()` | 2 |
| `entry_is_legal` сравнивает с литералом `1e-3` вместо `LEVEL_EPSILON`, объявленной в том же файле | 2 |
| `apply_fall_damage` принимает неиспользуемый `_impact` | 2 |
| Полёт — 70-строчный блок внутри `step_layered` | 2 |
| `terraces_ramp_launches_the_tank` проверяет только НИЖНЮЮ границу дуги (`peak > 2.0`) — регрессия настройки ему невидима | 1 |
| Пороги `minImpact`/`fullImpact` продублированы в `src/config/game.js` и `src/config/render.js`, связаны только комментарием | 6 |
| `LEVEL_MAX = 7` зашит в `Tank.js` копией движковой `MAX_LEVELS` | 4 |
| `tilt.js` берёт `shear` параметром, а `lift` — импортом конфига | 5 |
| `Smoke.js` и `Dust.js` дублируют весь жизненный цикл частиц | — (вынесено, см. «Что сознательно не делаем») |

## Решения, принятые до начала работ

| Вопрос | Решение |
| --- | --- |
| Перелёт стен | Механика `clear_walls` остаётся в ядре, но становится **недостижимой штатным прыжком**: `jumpClearance` поднимается выше максимальной дуги, ограниченной новым `maxLaunchVz`. Карта, которой перелёт нужен, задирает `rampLaunchFactor`/`maxLaunchVz` сама. Правок в `vimp-engine` не требуется. |
| Урон падения | Новый параметр `fallDamageFreeHeight` (мёртвая зона в уровнях), урон `fallDamage · max(0, height − freeHeight)`. `fallDamage` поднимается 15 → 30, чтобы падение ровно с одного уровня стоило прежние 15 HP. |
| Объём танка | Экструзия корпуса срезами (тем же приёмом, что объёмы карты — `buildVolumeSlices`, `volume.slices`/`volume.sideTint`) **плюс** тинт по направлению наклона. |
| Формат плана | Многоэтапный: этот файл — индекс. |

## Инварианты, которые нельзя нарушить

1. **Хост и реплика зовут одни и те же функции в одном порядке.** Формулы —
   в `core/src/motion.rs` и `core/src/level.rs`; `Tank::update`
   (`core/src/tank.rs:417`) и `Predictor::step_inner`
   (`core/src/client/predictor.rs`) обязаны идти шаг в шаг. Паритет
   сторожит тестовый модуль внутри `predictor.rs`.
2. **Порядок полей кадра позиционный и живёт в шести копиях**:
   `TankRow::fields()` (`core/src/tank.rs:36`), `src/config/snapshot.js`
   (`m1.fields`), `src/client/snapshotFields.js`, `TANK_FIELD_*` в
   `core/src/client/mod.rs`, хвост `render_overlay` там же и
   `core/src/client/remote_tanks.rs::render_data`. Расхождение молчит.
3. **`PLAYER_STATE_LEN = 8` менять нельзя** — константа движкового крейта.
4. **Одноуровневая карта не должна заметить изменений**: при
   `slope_vec == [0,0]` и `Transit::Grounded` все формулы обязаны совпадать
   со старыми бит-в-бит.
5. **Никаких коммитов.** Работа остаётся в рабочем дереве (правило §6
   глобального CLAUDE.md).
6. **Документация парная**: любая функциональная правка обновляет и
   `docs/en/`, и `docs/ru/` в том же изменении.

Ручная проверка прыжка: `VITE_MAP='terraces' npm run dev`, команда `team1`,
первая точка респауна — подножие крутой рампы `0 → 2` носом на запад;
держать `W`.

Ручная проверка перелёта: `VITE_MAP='overpass' npm run dev`, заехать на
северную рампу (`x` 3…5, `y` 32…34) на полном газу.

## Что сознательно не делаем

- **Не выносим общий базовый класс эмиттера частиц** из `Smoke.js` и
  `Dust.js`. Дублирование реальное (пул, трение, `boundsArea`, тикер,
  `applyParallax` в `onRender` — ~120 строк почти дословно), но рефакторинг
  двух живых партов не относится ни к одной из пяти проблем и должен
  ехать отдельной задачей со своим планом.
- **Не трогаем `vimp-engine`.** Все решения плана умещаются в этот
  репозиторий.

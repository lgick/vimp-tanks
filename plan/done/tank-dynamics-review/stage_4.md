# Этап 4. Клиент: тень ложится на опору, а не в мировую точку ✅ выполнен

Закрывает проблему 4: «тень других игроков на `terraces` слишком далеко
уходит от танка и меняет своё расположение, если просто ехать; особенно
видно на верхних уровнях; у своего игрока смещается при поворотах. Тень
должна смещаться, если танк в воздухе; если танк едет — быть под ним».

## Диагноз

Проекция 2.5D (`src/client/parallax.js`): объект на высоте `h` уровней
рисуется смещённым ОТ центра камеры на `h · shear` долей расстояния до
него.

```js
export function offsetPoint(x, y, camera, k) {
  return { x: x + (x - camera.x) * k, y: y + (y - camera.y) * k };
}
```

`src/client/parts/Tank.js`:

- корпус — `_updateView`:
  `offsetPoint(worldX, worldY, camera, this._z * parallax.shear)`;
- тень — `_updateShadow`:

```js
    // тень остаётся в МИРОВОЙ точке: высоту показывает разъезд корпуса с
    // ней, а сама она лежит на земле и никуда не уезжает
    shadow.x = this._worldX;
    shadow.y = this._worldY;
```

То есть тень нарисована так, будто она лежит на **уровне 0**, а корпус —
на своей высоте. Разъезд между ними равен

```
|тень − корпус| = z · shear · |позиция − центр камеры|
```

При `shear = 0.22` и танке на уровне 2 (`terraces`, верхняя площадка),
отстоящем от центра экрана на 500 мировых единиц, разъезд
`2 · 0.22 · 500 = 220` единиц — около 17 тайлов. И он **меняется, пока
танк едет**, потому что меняется расстояние до центра камеры. Ровно то,
что описано в отчёте.

У своего танка расстояние до центра камеры мало, но не ноль (камера
следует за танком с задержкой и ведёт себя по-своему на поворотах),
поэтому тень «подрагивает» — тоже ровно как в отчёте.

Комментарий «высоту показывает разъезд корпуса с ней» описывает
правильную идею, но применяет её не к той высоте: разъезд обязан
показывать высоту танка **над опорой**, а не над нулём карты. Стоящий на
плите уровня 2 танк над опорой не поднят вовсе — его тень обязана лежать
ровно под ним.

## Решение

Тень получает собственную высоту проекции — высоту **поверхности под
танком** — и рисуется той же `offsetPoint`, что и корпус. Разъезд тогда
равен `(z − groundZ) · shear · расстояние`, то есть:

- танк едет по плите или по рампе: `z == groundZ` ⇒ разъезда нет, тень под
  корпусом (и из-под него не выглядывает — за это отвечает
  `shadow.sizeFactor = 1.05`);
- танк в полёте: `z > groundZ` ⇒ тень отстаёт ровно на высоту подъёма — то
  самое, ради чего тень и заведена;
- танк падает с обрыва: `z` уходит НИЖЕ уровня отрыва, а опорой всё ещё
  считается уровень отрыва ⇒ тень остаётся на покинутой плите, и падение
  читается как удаление от неё.

### Откуда берётся `groundZ`

Из кадра, без новых полей. В `core/src/level.rs::step_layered` на всём
протяжении полёта `state.level` остаётся уровнем ОТРЫВА (он меняется
только в момент приземления), а `z` ведётся дробным. Вне полёта `z`
равно либо целому уровню (плита), либо высоте прогона рампы — и в обоих
случаях это и есть высота опоры.

Значит:

```
groundZ = (танк в полёте) ? this._level_из_кадра : this._z
```

Признак полёта — `vz !== 0` (то же правило, что у `Predictor`:
«ненулевая вертикальная скорость в кадре — полёт сама по себе»). После
этапа 3 `vz` приходит нештучно-сглаженным (`interp: 'discrete'`), так что
признак надёжен и для чужих танков.

**Важно**: нужен ФИЗИЧЕСКИЙ уровень из кадра (`data[M1_LEVEL]`), а не
`renderLevel(...)`, который уже поправлен под отрисовку. Сейчас
`Tank.js` сохраняет только результат `renderLevel` в `this._level` —
придётся завести отдельное поле.

### Правки в `src/client/parts/Tank.js`

**1. Сохранять физический уровень.** В конструкторе, рядом с `this._z`:

```js
    // ФИЗИЧЕСКИЙ уровень из кадра (не `renderLevel`): в полёте он держит
    // уровень отрыва, и по нему тень знает, над какой плитой висит танк
    this._physLevel = data[M1_LEVEL] || 0;
```

В `update` — рядом с `this._z = data[M1_Z] || 0;`:

```js
    this._physLevel = data[M1_LEVEL] || 0;
```

**2. Высота опоры.** Новый приватный геттер рядом с `_applyTilt`:

```js
  // Высота ПОВЕРХНОСТИ под танком в уровнях. На плите и на рампе это сама
  // высота корпуса (танк лежит на опоре), в полёте — уровень отрыва: его
  // ядро держит в `level` всю дугу (`core/src/level.rs`, `step_airborne`).
  // По ней рисуется тень: разъезд корпуса с тенью обязан показывать
  // подъём НАД ОПОРОЙ, а не высоту над нулём карты — иначе стоящий на
  // верхнем ярусе танк уезжает от своей тени тем дальше, чем дальше он от
  // центра экрана
  _groundZ() {
    return this._vz !== 0 ? this._physLevel : this._z;
  }
```

**3. `_updateShadow`.** Заменить блок позиционирования. Камера уже
вычислена в `_updateView`; чтобы не считать её дважды, передать параметром:
`this._updateShadow(camera)`.

```js
  _updateShadow(camera) {
    …создание тени без изменений…

    const groundZ = this._groundZ();

    // тень лежит НА ОПОРЕ и живёт в той же проекции, что корпус и плита
    // под ним: пока танк едет, обе точки совпадают и тень не видна
    // из-под корпуса; в полёте расходятся ровно на подъём над опорой
    const view = offsetPoint(
      this._worldX,
      this._worldY,
      camera,
      groundZ * parallaxConfig.shear,
    );

    shadow.x = view.x;
    shadow.y = view.y;
    shadow.rotation = this.rotation;

    // масштаб и прозрачность читают ПОДЪЁМ над опорой, а не высоту над
    // нулём карты: у стоящего танка подъёма нет, и тень обязана быть
    // такой же плотной на земле и на верхнем ярусе
    const lift = Math.max(0, this._z - groundZ);

    shadow.scale.set(this._shadowScale * (1 + lift * shadowConfig.scaleGain));
    shadow.alpha =
      Math.max(0, shadowConfig.baseAlpha - lift * shadowConfig.alphaFalloff) *
      this.alpha;

    // тень лежит на слое, НАД которым висит танк
    shadow.zIndex = levelZ(TANK_BASE_Z - 1, Math.min(LEVEL_MAX, Math.floor(groundZ)));
  }
```

Обратить внимание: масштаб тени раньше рос от `this._z`, то есть тень
стоящего на втором ярусе танка была на 20 % крупнее и на четверть
прозрачнее наземного. Это была компенсация той же ошибки проекции; теперь
она не нужна и вредна.

**4. `LEVEL_MAX`.** Константа `LEVEL_MAX = 7` в `Tank.js` — копия
движковой `MAX_LEVELS` (`vimp-engine`, `core/src/map.rs`, комментарий
«0..7, бит 8 занят `STATIC_LEVEL_GROUP`»). Копия остаётся (импортировать
из WASM в парт нечего), но комментарий обязан назвать источник точно:

```js
// потолок уровней карты: движок нумерует их 0..7 (бит 8 занят
// STATIC_LEVEL_GROUP, vimp-engine core/src/map.rs). Копия, потому что
// парту WASM-констант не отдают; расходиться с движком ей нельзя
const LEVEL_MAX = 7;
```

## Тесты

`tests/client/parts/Tank.test.js`. Фикстуры парта там уже есть; камеру
даёт `levelView`/`renderer`-заглушка — посмотреть, как это сделано в
существующих тестах тени, и повторить.

1. **`тень стоящего на верхнем ярусе танка совпадает с корпусом`**:
   `z = 2`, `level = 2`, `vz = 0`, камера смещена на 500 единиц по `x`;
   после `onRender` `Math.abs(shadow.x - tank.x) < 1e-6` и то же по `y`.
   Это прямой регрессионный тест проблемы 4 — до правки разница была ≈ 220.
2. **`тень не двигается относительно корпуса, пока танк едет`**: два
   кадра с разными `x` при том же `z = 2`, `vz = 0`; разность
   `shadow.x − tank.x` одинакова (и равна нулю) в обоих.
3. **`в полёте тень отстаёт от корпуса`**: `level = 2`, `z = 2.3`,
   `vz = -2`; `shadow.x !== tank.x`, и разность растёт при увеличении `z`.
4. **`падение с обрыва оставляет тень на покинутой плите`**: `level = 1`,
   `z = 0.4`, `vz = -4` ⇒ `groundZ === 1`, тень нарисована в проекции
   уровня 1.
5. **`масштаб и прозрачность тени считают подъём над опорой`**: у двух
   стоящих танков (`z = 0` и `z = 2`, оба `vz = 0`) `shadow.scale` и
   `shadow.alpha` совпадают.

## Проверка этапа

```bash
npx eslint . && npm test && npm run build && npm run sim:scenarios
```

Ручная: `VITE_MAP='terraces' npm run dev`. Проехать по верхней площадке
из угла в угол — тень обязана оставаться под корпусом на всём пути. Съехать
с края — тень остаётся на плите, корпус уходит вниз.

## Оговорка для исполнителя

Признак полёта `vz !== 0` у своего танка работает и до этапа 3 (его строка
идёт мимо интерполятора), а у чужого — только после него. Если этап 4
делается раньше этапа 3, тесты будут зелёными, а чужая тень в бою будет
дёргаться на границе кадров. Порядок 3 → 4 предпочтителен, но не
обязателен: правки не пересекаются по файлам.

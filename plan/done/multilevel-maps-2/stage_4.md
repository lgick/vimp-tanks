# Этап 4. T, ядро: стрельба, взрывы, бомбы, боты на N уровнях ✅ выполнен

**Репозиторий:** T. **Зависит от:** 3. Независим от 5 и 6.

**Файлы:** `core/src/shot_levels.rs`, `core/src/tanks.rs`
(`process_hitscan`, `create_weapon_action`, `detonate`),
`core/src/bomb.rs`, `core/src/bots/controller.rs`, `core/tests/sim.rs`.

## Цель

Перенести правила стрельбы и взрывов с «земля + одна плита» на
произвольное число уровней, сохранив каждое правило дословно.

## 4.1 Сегменты луча — переписать под N

`core/src/shot_levels.rs` написан ровно на два уровня:

* `let Some(grid) = levels.grid(1) else { return ground_only(range) };`
  (:43) — читается **только** грид уровня 1;
* ветка `level >= 1` (:69-104) ищет первую клетку без плиты уровня 1 и
  даёт максимум два сегмента `[1][0]`;
* ветка `level == 0` (:106-172) пробует ровно одну первую клетку с
  плитой уровня 1 (`t_slab` … `t_exit`).

Правила остаются теми же, но обобщаются:

**Вниз.** Луч держит уровень `L`, пока в клетке есть `floor(L)`; в первой
клетке без него падает на `levels.landing_level(L, cell_center)` и
продолжает там же — цикл, а не одна развилка. Сегментов может быть до
`N`. Уровень 0 — терминальный (земля есть везде внутри карты).

**Вверх (окно у кромки).** В первой клетке, где есть `floor` ближайшего
уровня выше `L`, луч получает окно ровно на эту клетку (`t0 = t_slab`,
`t1 = t_exit` — точный выход из клетки уже считается обходом, не оценкой
диагонали: это исправление кодревью 4.1, не потерять его) — если клетка
не `walls` того уровня (перила закрывают кромку). Дальше плита
экранирует, луч продолжает на своём уровне.

Сохранить обе тонкости кодревью:

* знак нуля в «клетке позади» (кодревью 4.2): `step(d) = if d > 0 {1}
  else if d < 0 {-1} else {0}` — для осевого луча иначе проверяется
  диагональный сосед;
* если луч уходит за границу сетки сразу за клеткой плиты, следующего
  визита нет и `t_exit` остаётся равным `range` — безвредно и оставлено
  осознанно.

**Одноуровневая карта** по-прежнему возвращает `ground_only(range)`
бит-в-бит — путь стрельбы старых карт не меняется.

`covers_level(segments, t, level)` и `level_at_distance(segments, t)`
править не нужно: они generic-обходы списка, просто списки станут
длиннее. `level_at_distance` по-прежнему нужен правилу `endLevel`
промаха (кодревью 4.4): уровень берётся на `t = range`.

## 4.2 Бомбы и взрывы

`TanksSim::create_weapon_action` (`core/src/tanks.rs:~1056-1068`) кладёт
бомбу на землю всякий раз, когда под точкой нет плиты своего уровня, и
когда стрелок падает:

```rust
let mut level = owner.level_state.level;
if owner.level_state.input_locked() { level = 0; }
else if let Some(levels) = self.levels.as_ref() {
    if level >= 1 && !levels.has_floor(level, x, y) { level = 0; }
}
```

Заменить оба «`= 0`» на `levels.landing_level(level, x, y)`: на карте из
трёх уровней бомба, брошенная над разрывом плиты уровня 2, обязана лечь
на плиту 1, а не улететь на землю. Тест
`bomb_dropped_over_the_void_lands_on_the_ground` переписать под новую
формулировку и добавить случай с промежуточной плитой.

Экранирование взрыва (`TanksSim::detonate`, `tanks.rs:~1116-1183`)
обобщается само: оно уже работает через `level_group(bomb.level)` и
членство коллайдера в группах — после этапа 1.1 группы стали
поуровневыми, и правило «взрыв поражает только свой уровень» продолжает
действовать на любом N.

## 4.3 Боты

`core/src/bots/controller.rs` уже уровнево-осведомлён: `PathPoint { pos,
level }`, `my_level`, выбор цели «сначала свой уровень» (~:449-460),
гейт стрельбы через `covers_level` (~:582-600), расширенный радиус
достижения точки при смене уровня (~:404-413).

Что проверить и поправить:

* найти оставшиеся сравнения уровня с константой 1 (если есть) и
  заменить на сравнение с `my_level`/`level_count`;
* ребро-обрыв в нав-графе стало дороже пропорционально высоте
  (этап 1.3) — убедиться, что `bot_path_crosses_the_ramp` и
  `scripted_bot_drives_onto_the_bridge` (`core/tests/sim.rs`) остались
  зелёными, а бот не начал предпочитать прыжок с трёх уровней;
* бот не должен пытаться заехать на рампу не с торца — после этапа 3.2
  путь через рампу строится нав-графом от подножия, но проверить, что
  точка подхода лежит перед торцом, а не сбоку.

## Отклонения

* **4.1.** Обход стал единым циклом `walk_ray_cells` вместо трёх веток:
  падение и окно решаются в одном колбэке, сегменты копятся по ходу, окно
  дописывается последним элементом списка (порядок «сначала свой уровень,
  потом проба» сохранён — от него зависят прежние тесты). Размеры сетки
  берутся у грида уровня 0, а не 1: гриды уровней одинаковы, а уровня 1 на
  карте могло бы не быть. Обе тонкости кодревью (знак нуля, `t_exit` по
  входу в следующую клетку) сохранены дословно.
* **4.2.** В `create_weapon_action` обе ветки свёрнуты в одну: `landing_level`
  зовётся и при `input_locked`, и над разрывом плиты. Ветка `input_locked`
  на практике недостижима игроком (`Tank::process_input` не производит
  выстрел при заблокированном вводе) — оставлена как защитная, тест
  `bomb_dropped_over_the_void_lands_on_the_slab_below` бьёт по второй ветке
  (танк на верхней половине рампы 1 → 2 над плитой уровня 1).
  `bomb_dropped_over_the_void_lands_on_the_ground` оставлен зелёным,
  переформулирован комментарий (на двухуровневой карте ближайшая опора и
  есть земля).
* **4.3.** Правок в `bots/controller.rs` не потребовалось: сравнений уровня
  с константой 1 в логике нет (только в фикстурах тестов), уровень везде
  берётся из `my_level`/`tank_level()`. `bot_path_crosses_the_ramp`,
  `scripted_bot_drives_onto_the_bridge`, `bot_holds_fire_through_the_slab`
  и `bots_fight_each_other` зелёные без изменений; подход к рампе строит
  нав-граф движка, гейт этапа 3.2 отсекает заезд сбоку.
* **Наблюдение для этапа 5.** Клиентская реплика бомбы
  (`core/src/client/shot.rs:~370`) всё ещё кладёт бомбу на землю
  (`level = 0`) вместо `landing_level` — хост и клиент на карте из трёх
  уровней разойдутся картинкой. Файл принадлежит этапу 5, поэтому здесь не
  тронут.

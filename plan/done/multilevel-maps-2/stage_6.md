## Ограничения сцены — нарушать нельзя

* **Плоская сцена.** Каждый парт — прямой ребёнок `app.stage`
  (`vimp-engine/src/client/components/view/Game.js`), порядок задаёт
  только `zIndex` через `levelZ(base, level) = base + LEVEL_Z_STRIDE *
  level`, `LEVEL_Z_STRIDE = 100` (`src/client/levelZ.js`). Базовые
  значения: `Tracks` 1; `Bomb`/`TankRadar`/`MapRadar`/`ShotEffect`/
  воронка 2; `Tank` 3; `Smoke`/взрыв 4; слои карты — из `data.layer`.
  Отдельные контейнеры создавать можно **только** как сиблинги на сцене
  — так уже сделано в `Tracks._markLayer` (и он же сам их уничтожает:
  движок про них не знает).
* **Камера — трансформ `app.stage`**, им владеет движок
  (`CanvasManagerView.updateCoords`: `stage.position = (w/2 - camX*scale,
  h/2 - camY*scale)`, `stage.scale = scale`). Движкового API «дай камеру»
  нет. Центр камеры в мире парт вычисляет сам:
  `camX = (w/2 - parent.position.x) / parent.scale.x` (и так же по y),
  где `w`/`h` — размер полотна.
* **`onRender` — аксессор** `Container.prototype`, а не метод. Назначать
  свойством в конструкторе (`this.onRender = () => …`); одноимённый метод
  подкласса затенит сеттер, и PixiJS никогда не вызовет колбэк. Тест
  обязан проверять **регистрацию** (`typeof part._onRender === 'function'`),
  а не тело — это правило записано в `CLAUDE.md` § Testing.
* **Один экземпляр PixiJS.** `pixi.js` — peer-зависимость, внешняя для
  сборки (`vite.config.js`). Фильтры писать через `Filter.from({ gl, gpu })`
  с обеими ветками.
* **Владение текстурами.** Запечённые ассеты общие на сессию — парты
  зовут `destroy({ texture: false, textureSource: false })`; исключение —
  `Map.mapSprite`, чья текстура сделана `renderer.generateTexture` под
  конкретный экземпляр карты и освобождается `textureSource: true`.
  Текстура `MapVolume` — того же рода, значит его `destroy` обязан её
  освобождать.

## 6.1 `levelView` → вид уровня

`src/client/levelView.js` (`createLevelView`, создаётся на ядро в
`hooks.services(core)`, пишет только локальный `Tank` через ленивое
`_isLocal()`), сегодня хранит `{ level, x, y }`. Расширить:

* добавить `z` (нужен тени и бейджу);
* добавить `alphaFor(level, worldX, worldY)` — единственная формула
  прозрачности на все парты (делегирует в `seeThrough.js`);
* добавить `mode` из конфига (см. 6.2), чтобы парты не читали конфиг
  каждый по-своему.

## 6.2 See-through: два режима (задачи 2, 3)

Решение пользователя: оба режима, переключаемых
`src/config/client.js` → `parts.seeThrough`:

```js
seeThrough: {
  mode: 'hole',        // 'hole' | 'layer'
  radius: 260,         // мировые единицы, режим 'hole'
  softness: 0.45,      // доля радиуса на затухание
  minAlpha: 0.12,      // прозрачность в центре дыры
  layerAlpha: 0.4,     // режим 'layer' — нынешний UNDER_BRIDGE_ALPHA
  fadeRate: 6,         // 1/с, сглаживание переключения (есть сегодня)
  lowerTint: 0xb0b0c0, // затемнение уровней НИЖЕ игрока
},
```

Новый модуль `src/client/seeThrough.js`:

```js
// alpha точечной сущности (ящик, чужой танк, дым, бомба, эффект)
export function seeThroughAlpha({ viewLevel, viewX, viewY, level, x, y, cfg });
// фильтр «дыры» для слоя карты; uniform'ы — центр в координатах кадра
// фильтра, радиус, мягкость, минимальная alpha
export function createHoleFilter(cfg);
```

Правила: гасится только то, у чего `level > viewLevel`; в режиме
`'hole'` — по расстоянию от игрока, в режиме `'layer'` — весь слой
целиком (нынешнее поведение, включая проверку `_hasFloorAt`).

Правки партов:

* **`Map.js`, статические слои уровня ≥ 1.** `_updateSeeThrough` вместо
  `this.alpha` двигает uniform'ы фильтра в режиме `'hole'`; в режиме
  `'layer'` — прежний код. Сглаживание `fadeRate` сохранить: без него
  проезд под кромкой моргает.
* **`Map.js`, ветка `type === 'dynamic'` (задача 2).** Сегодня
  `createDynamic` не назначает ни `onRender`, ни alpha — это и есть
  причина, по которой ящики не гаснут. Дать ей: `onRender` (назначением
  свойства), чтение уровня из строки кадра (`data[C_LEVEL]`, поле
  появилось на этапе 3.4) в `update()`, пересчёт
  `zIndex = levelZ(Number(data.layer) || 2, level)` при смене уровня и
  `this.alpha = seeThroughAlpha(...)`. Заодно ящик теперь умеет менять
  уровень на лету — падение с моста обязано быть видно.
* **Остальные парты**: `Tank.js`, `Smoke.js`, `Bomb.js`,
  `ShotEffectController.js`, `ExplosionEffectController.js` — та же
  `seeThroughAlpha`. Всё, что выше уровня игрока, гаснет вместе с плитой.

## 6.3 Признаки уровня (задача 3)

* **Затемнение нижних уровней.** Партам с `level < viewLevel` ставить
  `tint = cfg.lowerTint`. «Темнее — значит ниже» — так это читается в
  GTA 2, и это единственный признак, работающий на периферии экрана.
* **Бейдж уровня у своего танка.** Маленький значок с номером уровня под
  корпусом; рисуется только при `_isLocal()` и только на слоёной карте
  (иначе на `pool mini` появится «0»). Текстура — новый баке́р в
  `src/client/bakers/`, регистрация в `parts.bakedAssets.vimp`
  (`src/config/client.js`). Альтернатива, если бейдж окажется шумным:
  цветное кольцо вокруг корпуса в цвете уровня (та же палитра, что у
  радара) — решать по картинке.
* **Радар.** `MapRadar` уже красит стены по уровню
  (`LEVEL_COLORS = [0xffffff, 0x8fb7ff]`) — расширить палитру до
  `MAX_LEVELS` и гасить уровни, отличные от уровня игрока. `TankRadar` —
  добавить отметку уровня чужого танка (сегодня в коде прямо записано,
  что её нет; это пункт отложенного из прошлой итерации).

## 6.4 Тень и ракурс на рампе (задача 4, визуальная половина)

Сегодня единственная подсказка высоты — `zScale = 1 + z * Z_SCALE_GAIN`
(`Z_SCALE_GAIN = 0.06`) в `Tank.js`, и в комментарии там же записано, что
отдельная тень отложена. Пора:

* **Тень** отдельным спрайтом (баке́р `tankShadowTexture`, мягкий круг —
  рядом уже есть `blurredCircleTexture`): смещение
  `d = (позиция танка − центр камеры) * shadowShear * z`, размер растёт,
  прозрачность падает с `z`. Рисуется на слое уровня, **над** которым
  танк висит: `zIndex = levelZ(TANK_BASE_Z - 1, Math.floor(z))`. Тень —
  главный и самый дешёвый признак высоты; она же делает понятным, что
  танк едет по рампе, а не по земле.
* **Ракурс корпуса.** К `zScale` добавить продольное сжатие на подъёме:
  корпус, едущий «в горку от камеры», короче. Уклон клиент
  восстанавливает из `z` между кадрами (`Δz / Δs`, сглажено
  экспоненциально) — схему `m1` не трогаем (решение 4 мастер-плана).
  Если восстановление окажется шумным, сжатие признаётся необязательным:
  пара «тень + масштаб» уже читается, и лишний дрожащий эффект хуже его
  отсутствия. Решение принять по картинке и записать в «Отклонения».
* **Пыль из-под гусениц** на подъёме — переиспользовать `Smoke`/
  `ParticlePool` (частицы уже пулятся, `ParticleContainer` + `Particle`).

## 6.5 Объёмные элементы (задача 7)

Новый парт `MapVolume` — экструзия рендер-слоя, смещающаяся при движении
камеры.

**Регистрация** (иначе парт просто не будет создан и никакой ошибки не
будет): `src/client/parts/index.js`; в `src/config/client.js` —
`parts.gameSets.c1`/`c2` (добавить `'MapVolume'`),
`parts.entitiesOnCanvas.MapVolume: 'vimp'`,
`parts.componentDependencies` (`renderer`, `assetsBase`, `levelView`).
Сервисы игры перечислены в `ClientPlugin.serviceNames` — новый парт
сервисов не добавляет, но зависимости обязаны совпасть, иначе правило
`C4` ругается, а сервис молча приходит `undefined`.

**Данные.** Парт получает те же контексты `s0..sN`, что и `Map`, и
работает только с теми, у кого `data.volume > 0` (поле пришло из
`volumes` карты через движок, этапы 1.6 и 2.1). Остальные игнорирует
целиком: ни сетки, ни `onRender`.

**Геометрия.** Печёт текстуру своего слоя тем же приёмом, что
`Map.createStatic` (спрайты тайлов во временный контейнер →
`renderer.generateTexture({ target, frame })`), и строит по ней сетку
(`MeshPlane`-подобную, узлы по клеткам тайлов). Рисует её `K` срезами
(`K ≈ 4`) с растущим смещением вершин: для вершины в мировой точке `p`

```
d_i = (p − центр камеры) * volume * shear * (i / K),  i = 1..K
```

нижние срезы затемняются (боковые грани), верхний рисуется поверх
(`zIndex = levelZ(base, level) + 0.5`). Базовый слой `Map` остаётся на
месте и служит «основанием» блока.

Почему срезами, а не по блокам: экструзия стоит `K` вызовов отрисовки
независимо от числа стен. На 80 × 60 поблочная геометрия (сотни
четырёхугольников с пересчётом каждый кадр) — единственный способ
гарантированно уронить fps.

**Пересчёт** — в `onRender`, от центра камеры (см. «Ограничения сцены»).
Если камера не двигалась (сравнение с эпсилоном) — вершины не трогать.

**Конфиг** (`src/config/client.js`):

```js
volume: { enabled: true, slices: 4, shear: 0.22, sideTint: 0x9aa0aa },
```

Карта задаёт только высоту (`volumes`), всё остальное — вкус рендера.
`enabled: false` обязан полностью выключать парт — это путь отхода, если
на слабой машине эффект окажется дорогим.

## Тесты (`tests/client/`)

Идиомы репозитория: фейковые `dependencies` объектом-литералом
(`{ renderer, assetsBase, levelView, localPlayer, soundManager }`),
`Assets.load` подменяется невыполняющимся промисом
(`vi.spyOn(Assets,'load').mockImplementation(() => new Promise(() => {}))`),
готовность статического слоя имитируется присвоением `map.mapSprite = {}`,
фейк `localPlayer` — `{ is: id => String(id) === String(myId) }`,
эффекты добавляются в обычный `new Container()` вместо `app.stage`.

Проверять:

* **проводку** `onRender` у динамического слоя `Map` (сегодня её нет
  вовсе) и её отсутствие у слоя уровня 0;
* `zIndex` ящика меняется при смене `data[C_LEVEL]`, alpha — при смене
  уровня игрока в `levelView`;
* `seeThroughAlpha` — таблица случаев: свой уровень (1), выше и близко
  (`minAlpha`), выше и далеко (1), ниже (1 + tint), режим `'layer'`
  (весь слой);
* бейдж уровня появляется только у локального танка — фейк
  `localPlayer`, у которого `id` сначала `null` (парты строятся из
  `FIRST_SHOT_DATA` до того, как известен свой id — ровно тот случай,
  ради которого `_isLocal` стал замыканием);
* тень: смещение растёт с `z` и с расстоянием от центра камеры;
  `zIndex` тени — уровня под танком;
* `MapVolume`: при `volume = 0` сетка не строится и `onRender` не
  вешается; при `volume > 0` смещение вершины растёт с расстоянием от
  камеры; `destroy` освобождает свою текстуру.

## Отклонения

1. **Конфиг вынесен в `src/config/render.js`.** План клал `seeThrough` и
   `volume` в `src/config/client.js`, но партам движок конфиг не отдаёт:
   фабрика зовёт `new Part(data, assets, dependencies, context)`, где
   `dependencies` — только сервисы. Числа живут в отдельном модуле, который
   импортируют и `src/config/client.js` (кладёт их в `parts.seeThrough` /
   `parts.volume` — документация клиентского конфига), и сам клиентский код
   (`levelView`, `MapVolume`). Иначе значения пришлось бы дублировать.

2. **`levelView` получил больше, чем `z` + `alphaFor` + `mode`.** Добавлены
   `tintFor(level)` (признак «темнее — значит ниже» обязан быть такой же
   единственной формулой, что и alpha), `cfg` (плите нужны `radius`,
   `softness`, `minAlpha`, `fadeRate` для uniform'ов фильтра) и
   `markLayered()`/`layered` — иначе `Tank` не может узнать, слоёная ли
   карта, и бейдж уровня появился бы на `pool mini`.

3. **`bakeTileLayer.js` вынесен из `Map.createStatic`.** `MapVolume` печёт
   ту же картинку тем же приёмом; копия кода означала бы, что объём и его
   основание могут разъехаться.

4. **Палитра уровней вынесена в `src/client/levelColors.js`** и расширена
   до `MAX_LEVELS = 8` (её делят `MapRadar` и `TankRadar`). Отметка уровня
   чужого танка сделана кольцом в цвете уровня — тем самым запасным
   вариантом, который план разрешал выбрать «по картинке»: цифра на маркере
   радара в масштабе 1:8 нечитаема.

5. **Ракурс корпуса оставлен** (план разрешал признать его необязательным):
   уклон восстанавливается сглаженно (`src/client/grade.js`, экспоненциальное
   сглаживание + порог на неподвижный танк), поэтому дрожания нет. Тот же
   трекер уклона питает пыль из-под гусениц в `Smoke`.

6. **`Tank` получил зависимость `renderer`.** Центр камеры парт вычисляет
   сам (движкового API нет), а для этого нужен размер полотна —
   `renderer.screen`. Помощник общий: `src/client/camera.js`.

7. **`levelView` роздан ещё и `MapRadar`** (гашение чужих уровней на схеме)
   помимо перечисленных в плане партов.

8. **Глазами (`npm run dev`) этап не проверялся** — в сессии нет дисплея, а
   карта `terraces` появляется только на этапе 7. Вместо этого зелены
   `npx eslint .`, `npm test` (227 тестов), `npm run build`,
   `node bin/vimp-contract.js --game .` (36 правил) и `npm run sim:scenarios`
   (8 сценариев). Визуальную приёмку обоих режимов `seeThrough` и объёма
   принимает на себя этап 8.

# Многоуровневые карты 2.5D, итерация 2 (GTA 2) — мастер-план

> Статус: выполнен, этапы 0—8 закрыты.

Первая итерация (`plan/done/multilevel-maps/`) и кодревью к ней
(`plan/done/review_2_5d.md`) дали ровно **два** уровня: землю (0) и одну
эстакаду (1), направленные рампы, падение с обрыва, стрельбу между
уровнями, ботов и демо-карту `overpass`. Всё выпущено:
`vimp-engine-core 0.11.0`, `vimp-engine 0.30.1`, `@vimp-games/tanks 0.17.1`.

Эта итерация закрывает восемь задач пользователя.

## Принятые решения

Не пересматривать без явной команды пользователя.

1. **Слои остаются фичей движка.** Формат карты, геометрия, нав-граф,
   транспорт `MAP_DATA` и тела карты принадлежат `vimp-engine-core`. Всё,
   что касается «сколько бывает уровней», «куда падает тело» и «что такое
   высота тайла», правится в **E**, а не в танках.
2. **`MAX_LEVELS = 8`** (решение пользователя). Уровни занимают биты 0..7
   маски Rapier (`GROUP_1..GROUP_8`), `STATIC_LEVEL_GROUP = GROUP_9`
   (бит 8) остаётся на месте — переезжать ему не нужно.
3. **Формат карты аддитивен.** Карта без `levels` идёт прежним путём
   бит-в-бит (`ground_only` в луче, ветка `NavigationSystem::generate`,
   отсутствие фильтра групп в хитскане). Новое необязательное поле —
   `volumes` (высоты рендер-слоёв, только визуал).
4. **Кадр `m1` НЕ меняется.** `z: f32` и `level: u8` уже есть, меняется
   только диапазон `z` (0..N). `PLAYER_STATE_LEN = 8`,
   `ENGINE_API_VERSION = 4` — не трогаем; ABI ядра расширяется только
   append-only (макросы `abi.rs` заморожены, `surface.json` — тоже,
   добавления в него допустимы).
5. **Строка `c1`/`c2` расширяется** полями `z`/`level`. Её пишет
   **движок** (`GameMap::dynamic_map_data`), поэтому запись включается по
   объявленной игрой схеме: игра, не объявившая `z`/`level`, получает
   прежнюю строку (обязательно для `vimp-snakes`).
6. **Падение — общий примитив движка.** Одна траектория на танки и на
   ящики; игра добавляет поверх свои правила (блокировка ввода, урон).
7. **Объёмные элементы: высота — поле карты `volumes`** (решение
   пользователя). Движок валидирует его и протаскивает в контекст парта,
   геометрию строит `MapVolume` в танках.
8. **Прозрачность верхних уровней — два режима, переключаемых конфигом**
   (решение пользователя): `seeThrough.mode: 'hole'` (радиальная дыра
   вокруг игрока, по умолчанию) и `'layer'` (нынешняя alpha на весь слой,
   запасной путь). Оба покрываются тестами.
9. **Старые карты не правятся.** `canopy`, `garden`, `pool mini` — ни
   строки; `overpass` — только опциональные `volumes` и возврат ящиков к
   разрывам перил (ограничение снимается задачей 1).

## Глоссарий

| Термин | Значение |
| --- | --- |
| **Уровень (level)** | Дискретный этаж карты, `u8`. 0 — земля, 1..7 — надземные. |
| **z** | Непрерывная высота `0.0..N` для визуала и правил: подъём по рампе, падение. `f32`. |
| **Плита (floor)** | Тайл уровня, по которому можно ездить. Непрозрачен для луча снизу. |
| **Перила (walls)** | Тайл уровня, блокирующий движение и луч на этом уровне; закрывает край от выстрела снизу. Обязан входить и в `floor`. |
| **Обрыв (ledge)** | Граница плиты без перил. С него падают. |
| **Рампа (ramp)** | Направленный прогон тайлов уровня `from`, по которому `z` меняется `from → to`. |
| **Прогон (RampRun)** | Максимальная непрерывная последовательность тайлов рампы вдоль её оси в одной строке/колонке. |
| **Уклон (grade)** | Продольная составляющая крутизны под курсом танка: `slope * dot(dir, heading)`. |
| **Объём (volume)** | Визуальная высота рендер-слоя в уровнях; экструзия в `MapVolume`. |

## 6.1 Пайплайн: webm не проходит ни через один фильтр (Д10)

### Диагноз

`scripts/process-audio.js:87-102`:

```js
const audioFilters = [
  `silenceremove=start_periods=1:start_threshold=${SILENCE_THRESHOLD}`,
  `loudnorm=I=${LOUDNESS.I}:LRA=${LOUDNESS.LRA}:tp=${LOUDNESS.TP}`,
].join(',');

const command = [
  'ffmpeg', '-nostdin', `-i "${sourcePath}"`, '-hide_banner -loglevel error -y',
  `-af "${audioFilters}"`,                                             // :97
  `-c:a libmp3lame -q:a ${CODEC_SETTINGS.MP3_QUALITY} "${outputMp3}"`, // :99
  `-c:a libopus  -b:a ${CODEC_SETTINGS.WEBM_BITRATE} "${outputWebm}"`, // :101
].join(' ');
```

`-af` — **опция выхода**, она действует на следующий за ней файл. То есть
фильтры применяются только к mp3; webm получает сырой источник.

`src/config/sounds.js:33` объявляет `codecList: ['webm', 'mp3']`, а
`SoundManager.init` берёт **первый поддерживаемый** кодек
(E `packages/engine/src/client/SoundManager.js:57`). Chrome, Firefox и Edge
играют webm, то есть **ненормализованный** звук; mp3 — фактически ветка для
Safari.

Замер `ffmpeg ebur128` по текущему `build/sounds/` (интегральная громкость):

| файл | .mp3 (с фильтрами) | .webm (без) |
| --- | --- | --- |
| tank-engine | −16.0 LUFS | **−20.6** |
| shot | −14.2 | −12.0 |
| explosion | −15.0 | **−9.6** |
| hit | −17.3 | −15.7 |
| frag | −16.0 | −17.3 |
| round-start | −15.8 | −14.4 |

mp3 стоит на цели `I = −16`; webm разбросан на **11 LU**. Двигатель — самый
тихий в наборе, взрыв на 11 LU громче него. Отсюда «двигатель пропадает,
вместо него гул».

### Правка

Указать цепочку фильтров **для каждого выхода**:

```js
const command = [
  'ffmpeg', '-nostdin', `-i "${sourcePath}"`, '-hide_banner -loglevel error -y',
  // -af — опция ВЫХОДА: указанная один раз, она действует только на
  // следующий файл. Раньше фильтровался лишь mp3, а webm (его и играет
  // Chrome) шёл сырым
  `-af "${audioFilters}" -c:a libmp3lame -q:a ${CODEC_SETTINGS.MP3_QUALITY} "${outputMp3}"`,
  `-af "${audioFilters}" -c:a libopus -b:a ${CODEC_SETTINGS.WEBM_BITRATE} "${outputWebm}"`,
].join(' ');
```

(Двойной прогон фильтра дешевле, чем `-filter_complex` с `asplit`, и читается
лучше. Если понадобится один проход — вариант с `asplit` тоже допустим,
решение записать.)

### Проверка — скриптом, а не на слух

Добавить `scripts/check-audio-levels.js`: прогоняет `ffmpeg -i <file>
-af ebur128 -f null -` по каждому файлу в `build/sounds/`, парсит
`Integrated loudness`, печатает таблицу и **завершается ненулевым кодом**,
если какой-то файл отклонился от `LOUDNESS.I` больше чем на 1 LU. Вызывать
после `npm run build` вручную; в CI не включать без отдельного решения
(нужен ffmpeg на раннере).

## 6.2 Петля двигателя щёлкает (вторая половина «гула»)

`silenceremove` снимает тишину только в начале, и к webm он вообще не
применялся. Замеры длительностей:

| файл | длительность |
| --- | --- |
| `tank-engine.wav` (источник) | 0.647823 с |
| `tank-engine.mp3` | 0.647833 с |
| `tank-engine.webm` | **0.655000 с** |

Opus дописал ~7 мс. На петле длиной 0.65 с это тишина ~1.5 раза в секунду —
периодический щелчок, который на слух и есть «гул» вместо ровного холостого
хода.

Варианты (выбрать один, решение записать):

1. Обрезать хвост в пайплайне: добавить в цепочку
   `atrim=end=<длительность источника>` или `apad`+`atrim` для webm;
   проверить, что итоговая длительность совпала с источником.
2. Задать точку петли в конфиге: Howler поддерживает `sprite` с явными
   границами — `src/config/sounds.js`, `tankEngine: { ..., sprite: {
   loop: [0, 647, true] } }`. Требует правки регистрации в движке
   (`_internalPlay` зовёт `sound.play()` без имени спрайта) — если движок не
   готов, идти вариантом 1.

После правки прослушать двигатель 30 секунд подряд: периодического щелчка
быть не должно.

## 6.3 Свой танк и свой выстрел звучат по центру (Д9)

### Диагноз

E `packages/engine/src/client/SoundManager.js:91` вешает
`pannerAttr(PANNER_SETTINGS)` на каждый звук, `panningModel: 'HRTF'`
(`:11`). Слушатель — центр камеры (`main.js:893`), камера — предсказанная
позиция своего танка (`core/src/client/mod.rs:370`). Значит свой двигатель
почти всегда попадает в ветку `_updateSpatialSound:431`:

```js
sound.pos(0, 0, 0, soundId); // "отключение панорамирования"
```

Панорама не отключается — источник ставится ровно на слушателя, и браузер
сворачивает петлю с фронтальной HRIR. Это спектральная окраска (не
затухание: `distanceModel: 'inverse'` с `refDistance: 150` держит усиление
1.0) — то самое «вместо звука двигателя гул».

Когда камера и танк расходятся хотя бы на 2 пикселя (спектатор, сброс
камеры, кадр, где камера пришла из `HOT_FLAGS.CAMERA`, а танк —
интерполирован), срабатывает ветка `:429`, и, поскольку азимут в Web Audio
зависит от **направления**, а не от расстояния, свой звук уезжает в одно ухо
целиком. `MIN_SPATIAL_DISTANCE = 1` (`:7`) от этого не спасает.

Свой выстрел: `src/client/parts/effects/shot/ShotEffectController.js:28-29,
80-83` берёт позицию **корпуса стрелка на момент выстрела**
(`W1_BODY_X/Y`), звук одноразовый и позиционируется один раз, в
`processAudibility` (`SoundManager.js:305-311`). Предсказанный локальный
выстрел и его авторитетное эхо не совпадают по позиции — один и тот же
выстрел звучит то по центру, то в ухо.

### Правка (движковая половина — этап 2.6)

В танках:

1. `src/client/parts/Tank.js`, `_getSoundData()`:

   ```js
   return {
     position: { x: this._worldX, y: this._worldY },
     rate,
     volume: this._baseEngineVolume * volumeFactor,
     // свой двигатель не принадлежит миру: он всегда по центру и без HRTF,
     // иначе источник, лежащий на слушателе, звучит как гул, а расхождение
     // камеры и танка в пару пикселей кидает его в одно ухо
     spatial: !this._isLocal(),
   };
   ```

   `_isLocal()` — существующее замыкание (`Tank.js:152`), считается каждый
   кадр, флаг обновляется через `updateSoundData` (`:308`).
   **Важно:** позиция обязана быть мировой и несмещённой (этап 4.4).

2. `ShotEffectController`: определить, свой ли это выстрел
   (сравнить владельца строки с сервисом `localPlayer`; если сервис парту не
   объявлен — добавить в `componentDependencies`), и передать
   `spatial: false`. То же рассмотреть для `Bomb` (`bombHasBeenPlanted`) и
   своего взрыва: решение записать — по умолчанию оставить их
   пространственными, они действительно принадлежат миру.

3. Проверить `MIN_SPATIAL_DISTANCE` (этап 2.6 поднимает его до ~половины
   тайла): подобрать так, чтобы близкий чужой танк не «прыгал» между ушами.

приёмки: **падает на расхождении кодеков** (это и есть регрессия Д10),
предупреждает об отклонении от цели больше 2 LU и пропускает файлы короче

### 6.2 — пропущено, диагноз плана не подтвердился

Решение пользователя: пропустить, записать замеры.

Замеры (`ffprobe`, `assets/audio-raw/tank-engine.wav` → 0.647823 с):

| файл | длительность контейнера | декодированный поток |
| --- | --- | --- |
| `tank-engine.mp3` | 0.647833 | 0.647833 |
| `tank-engine.webm` | 0.655000 | **0.647833** |

Лишние 7 мс живут только в метаданных: это encoder delay / discard padding
Opus, и декодер (ffmpeg, как и парсер WebM в Chrome) их отбрасывает —
декодированный webm совпадает с источником, `silencedetect` не находит
тишины ни в начале, ни в конце ни у одного из трёх файлов. Вариант 1 не
годится: длительность контейнера всегда равна декодированной + ~7 мс
(проверено на `atrim=end=0.6408` → контейнер 0.648, декодированный 0.6408),
то есть `atrim` не сравнял бы длительности, а просто отрезал бы 7 мс живого
звука. `-frame_duration 2.5` даёт 0.654 — тот же порядок.

Если щелчок останется после нормализации webm (6.1), причину искать не в
длительности, а в разрыве формы волны на стыке петли в самом источнике.
Вариант 2 (границы петли Howler-спрайтом + правка `_internalPlay` в
движке) остаётся доступным.

### 6.4 — пересчёт арифметический

Решение пользователя: пересчитать арифметически, не на слух. Каждое
значение домножено на 10^(−Δ/20), где Δ — замеренная разница webm до/после
нормализации (для `bomb-has-been-planted`, который короче окна гейтинга,
взята разница `mean_volume`: −26.0 → −27.6):

| звук | было | стало |
| --- | --- | --- |
| roundStart | 0.3 | 0.35 |
| victory | 0.3 | 0.38 |
| defeat | 0.3 | 0.5 |
| frag | 0.3 | 0.26 |
| hit | 0.3 | 0.36 |
| gameOver | 0.3 | 0.31 |
| shot | 0.4 | 0.51 |
| explosion | 0.4 | 0.74 |
| bombHasBeenPlanted | 0.4 | 0.48 |
| tankEngine | 0.5 | 0.29 |

**Важно:** такой пересчёт сохраняет прежний баланс целиком — взрыв
по-прежнему на ~9 дБ громче холостого хода. Если двигатель на слух всё ещё
теряется, значения правятся в `npm run dev` отдельно; выравненный пайплайн
это теперь позволяет (одно число `volume` значит одно и то же в любом
браузере).

**Решение по неиспользуемым файлам:** `empty-bullet` и
`bomb-has-been-planted2` оставлены как есть — исходники лежат в
`assets/audio-raw/`, в `src/config/sounds.js` не объявлены.

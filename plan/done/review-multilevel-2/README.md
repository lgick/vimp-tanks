## Корневая причина визуальных дефектов

**В системе нет высоты уровня в мировых единицах.** `z` меряется в уровнях
(0..N), всё остальное — в мировых пикселях, и эти величины смешиваются
напрямую. `RampSample::slope` (E `packages/engine/core/src/map.rs:981`)
считается как `rise / span`, то есть «уровней на пиксель».

На реальных картах (`scale: 0.4`, `step: 32` ⇒ тайл = 12.8 мировых единиц):

| Прогон | Перепад / длина | `slope` |
| --- | --- | --- |
| `terraces.rampLong` 0 → 1 | 1 уровень / 9 клеток | **0.0087** |
| `terraces.rampSteep` 0 → 2 | 2 уровня / 4 клетки | **0.039** |
| `overpass.rampNorth` 0 → 1 | 1 уровень / 3 клетки | **0.026** |

Все константы, подобранные под безразмерный уклон (`climbGravity: 220`,
`climbMaxSpeedFactor: 0.55`, `GRADE_SQUASH_GAIN: 0.35`, `DUST_CONFIG.minGrade:
0.05`), промахиваются в 30—100 раз. Отсюда: наклона корпуса не видно (≤ 1.4 %),
пыли не бывает никогда (порог выше любого реального уклона), торможение в
горку ≈ 0.9 % тяги.

**Решение (утверждено пользователем):** ввести `levelHeight` — поле карты,
валидируемое движком (мировых единиц на уровень, по умолчанию размер тайла).
Одно число чинит уклон в физике, наклон корпуса, пыль, параллакс слоёв и
экструзию объёмов.

## Принятые решения

Не пересматривать без явной команды пользователя.

1. **Правим оба репозитория.** Движковые правки выходят релизом до старта
   этапов танков — как в прошлой итерации.
2. **Рампа закрывается коллайдерами прогона** (борта + «неправильный» торец)
   через отдельную группу-«страж», плюс визуальный клин с нарастающей
   высотой. Не правилом и не разметкой `walls` в каждой карте.
3. **Высота уровня — поле карты `levelHeight` в движке.** Не константа
   рендера в игре: число нужно и физике, и рендеру, и валидации.
4. **Непространственный звук — флаг в движковом `SoundManager`**
   (`registerSound(name, { spatial: false })`), а не подмена позиции в игре.
5. **Формат карты остаётся аддитивным.** Карта без `levels` идёт прежним
   путём бит-в-бит; `levelHeight` необязателен и имеет дефолт.
6. **Кадр `m1` не меняется.** Наклон по-прежнему восстанавливается клиентом
   из `z`; в кадр он не едет.

### Почему без движка

Первое побуждение — слить параллельные прогоны в один широкий в
`MapLevels::build_runs` (E `packages/engine/core/src/map.rs:868`). Это
потребовало бы релиза `vimp-engine-core` (в T `wasm-pack` не принимает
`--config` с патчем, значит крейт обязан быть опубликован). Но
перестроение между полосами чинится в T целиком: физически внутренние
борта-стражи прозрачны для поднимающегося (`map::body_filter` снимает
`RAMP_GUARD_GROUP` у тела с `on_ramp()`), мешает только вердикт гейта в
`core/src/level.rs`, а это код T. Клин рампы — тоже T
(`src/client/parts/rampRuns.js` строит прогоны для картинки сам).

## Шаг 1. Широкая горка проезжается насквозь

### 1.1 Ядро: перестроение между полосами (`core/src/level.rs`)

Сейчас (`core/src/level.rs:262-265`):

```rust
let climbing = match state.transit {
    Transit::Ramp { climbing, run, .. } if run == ramp.run => climbing,
    _ => entry_is_legal(state, &ramp, cell, levels),
};
```

Переезд в соседнюю полосу — это другой `run`, значит `entry_is_legal`, а
там `if along.abs() != 1 || across != 0 { return false }`
(`level.rs:377-379`) — боковой шаг всегда незаконен ⇒ `climbing = false`,
`z` схлопывается в `state.level` (`level.rs:276-281`), возвращается бит
стража и танк упирается в борт своей полосы.

Правка — новая ветка `match` перед фолбэком на гейт:

```rust
let climbing = match state.transit {
    Transit::Ramp { climbing, run, .. } if run == ramp.run => climbing,
    // перестроение между ПОЛОСАМИ одной широкой горки. Движок режет блок
    // тайлов рампы на параллельные прогоны по строкам/колонкам
    // (`MapLevels::build_runs`), поэтому широкая горка — это N прогонов, и
    // без этого правила каждая межполосная граница судилась бы как новый
    // вход и обрывала бы подъём на середине
    Transit::Ramp { climbing, .. } if is_lane_change(levels, state.prev_cell, cell, &ramp) => {
        climbing
    }
    _ => entry_is_legal(state, &ramp, cell, levels),
};
```

Новая свободная функция рядом с `run_at_cell` (`level.rs:326`):

```rust
// Полосы ОДНОЙ широкой горки: прогоны, отличающиеся только положением
// поперёк оси. Сравниваются ось, знак подъёма, перепад и границы ВДОЛЬ
// оси — у полос одного блока они совпадают до бита (`min`/`max` считаются
// как индекс клетки * tile_size). Шаг обязан быть ровно на одну клетку
// ПОПЕРЁК оси: вход с торца по-прежнему судит гейт.
fn is_lane_change(
    levels: &MapLevels,
    prev: (i32, i32),
    cell: (i32, i32),
    ramp: &RampSample,
) -> bool {
    let Some(prev_run) = run_at_cell(levels, prev) else {
        return false;
    };

    let runs = levels.runs();
    let (Some(a), Some(b)) = (
        runs.get(prev_run as usize),
        runs.get(ramp.run as usize),
    ) else {
        return false;
    };

    let (dx, dy) = (cell.0 - prev.0, cell.1 - prev.1);
    let (along, across) = if ramp.axis == 0 { (dx, dy) } else { (dy, dx) };

    along == 0
        && across.abs() == 1
        && a.axis == b.axis
        && a.sign == b.sign
        && a.from == b.from
        && a.to == b.to
        && a.min == b.min
        && a.max == b.max
}
```

`MapLevels::runs()` публичен (E `map.rs:984`), поля `RampRun` тоже — новых
движковых API не требуется.

Записать в комментарии ограничение: полосы разной ДЛИНЫ (ступенчатый блок)
остаются разными горками — переезд между ними судит гейт. Это осознанно:
одинаковые `min`/`max` — и есть признак «одна широкая горка».

**Тесты** (`core/src/level.rs`, модуль `tests`, рядом с
`mask_on_a_ramp_covers_the_whole_run:739`):

- `lane_change_on_a_wide_ramp_keeps_climbing` — грид с блоком тайла рампы
  шириной 3 клетки; законный вход с подножия в полосу 0, затем шаг ПОПЕРЁК
  в полосу 1: `Transit::Ramp { climbing: true, .. }`, `z` продолжает расти,
  `on_ramp()` истинно;
- `lane_change_between_runs_of_different_length_is_a_new_entry` — блок, у
  которого средняя полоса короче: боковой переезд даёт `climbing = false`;
- `side_entry_is_still_refused` — регрессия: заезд сбоку с земли (`prev`
  вне любого прогона) по-прежнему `climbing = false`
  (`ramp_is_not_entered_from_under_the_bridge:694` не должен позеленеть

### 1.2 Клин: слияние полос в одну картинку (`src/client/parts/rampRuns.js`)

`buildRampRuns` повторяет обход ядра и возвращает по прогону на строку —
у широкой рампы получается три параллельные полосы, каждая со своими
юбками (шаг 2) ⇒ на картинке между ними встанут стенки, которых в физике
нет.

После цикла по рампам добавить слияние: прогоны с одинаковыми
`axis`, `sign`, `rise` и одинаковым интервалом ВДОЛЬ оси
(`col0/col1` при `axis === 1`, `row0/row1` при `axis === 0`) и смежными
интервалами поперёк (`row1 === row0` соседа) складываются в один прогон с
объединённым поперечным интервалом.

Реализация: ключ `${axis}|${sign}|${rise}|${main0}|${main1}`, группировка в
`Map`, сортировка группы по поперечной координате, свёртка соседних.

**Шапку файла переписать**: сейчас она обещает «тот же обход, что у ядра».
Теперь это неверно — записать явно: ядро держит полосы раздельно (вердикт
гейта на полосу), а клин рисует блок целиком, и разъезжаться этим двум
представлениям нельзя ни в чём, кроме ширины прогона.

**Тесты** `tests/client/parts/rampRuns.test.js`: блок 3 × N даёт ОДИН
прогон с `row0/row1` (или `col0/col1`) на всю ширину; блок со ступенчатым
краем даёт несколько прогонов; существующие проверки одиночных прогонов
остаются зелёными.

## Шаг 2. Горка — сплошная насыпь (юбки клина)

`src/client/parts/Map.js`, `_createRampMeshes` (`:349-431`).

Сейчас на прогон строится один `MeshSimple` верхней поверхности: полоса из
`segments = cells * volume.rampSegments` сегментов, у каждой вершины своя
высота `k = (level + rise * progress) * shear`, вершины в мировых единицах,
сдвиг считается поточечно в `_updateRampMesh` (`:471-486`). Под клином
видна земля — читается как пустота, в которую нельзя въехать.

Добавить **второй меш на прогон — юбку**:

- нижняя кромка каждой вершины: тот же мировой X/Y, но `k` базовой
  плоскости прогона — `kBase = this._level * shear` (`this._level` = уровень
  грида, в котором лежит тайл рампы, то есть НИЖНИЙ уровень прогона);
- геометрия: две продольные полосы (борт по `cross_min` и борт по
  `cross_max` — те же линии, где движок ставит коллайдеры-стражи,
  E `map.rs:1421-1425`) плюс торцевой четырёхугольник на ВЕРХНЕМ конце
  (`i = points - 1` при `run.sign > 0`, иначе `i = 0`); нижний торец
  остаётся открытым — это законный вход;
- вершины и `heights` в тех же массивах-парах, что у верхнего меша, чтобы
  `_updateRampMesh` работал без изменений (он уже общий: любой срез с
  полями `base`/`heights` считается поточечно);
- текстура — тот же `this._rampTexture`, UV берутся у соответствующей точки
  поверхности (вертикальный «протяг» пикселей кромки), `tint =
  volume.sideTint` — ровно как у боковых срезов объёма (`Map.js:283`);
- в массив срезов юбка кладётся с `k = kBase`, поэтому существующая
  сортировка `slices.sort((a, b) => a.k - b.k)` (`:327`) рисует её ДО
  верхней поверхности. Ближняя к камере грань видна, дальняя всегда
  накрыта поверхностью — выбирать сторону в рантайме не нужно;
- `destroy()` (`:635`): юбка — ребёнок того же контейнера, уходит по
  `children: true`; текстура клина освобождается там же и один раз
  (`rampTexture.destroy(true)`), новых владельцев не появляется.

Прогон `1 → 2` (у `terraces` это `rampStep`, лежит в гриде уровня 1 над
землёй) получает юбку до плоскости уровня 1: под ним остаётся видимый
просвет — и там проезд действительно есть (`level.rs:713-737`,
`mask_under_a_high_ramp_stays_on_the_ground_level`). Правило «видно пусто —
значит проехать можно» держится.

**Клин остаётся в контейнере своего слоя** (в отличие от объёма, шаг 4):
танк, поднимающийся по горке, обязан рисоваться ПОВЕРХ её поверхности.
Записать это решение в комментарии — иначе следующая правка «унифицирует»
клин с объёмом и спрячет танк под горкой.

**Конфиг** (`src/config/render.js`, блок `volume`): при необходимости
завести `skirtTint` (по умолчанию `= sideTint`) — только если по картинке
окажется, что общий `sideTint` для насыпи слишком светлый. Лишнего числа не
плодить.

**Тесты** `tests/client/parts/Map.test.js` (блок клина): у прогона ДВА
меша; у юбки нижние вершины сдвинуты на `level * shear`, верхние — на
`(level + rise * progress) * shear`, сдвиг монотонен вдоль прогона;
`destroy` уничтожает оба меша и освобождает текстуру клина ровно один раз.

## Шаг 4. Объём слоя перекрывает динамику своего уровня

`src/client/parts/Map.js`.

### 4.1 Отдельный контейнер-перекрыватель

- В `_createExtrusion` (`:272`) срезы ОБЪЁМА (ветка `this._volume > 0`,
  `:277-290`) добавляются не в `this`, а в новый `this._occluder` —
  `Container`, добавленный в `this.parent` (сцена), как это уже сделано с
  тенью танка (`Tank._updateShadow:371`). Контейнер единичный, поэтому
  `applyParallax(slice.target, camera, slice.k, this._baseScale)` работает
  без изменений: система координат та же.
- `zIndex` перекрывателя: `levelZ(Math.max(this._layer, OCCLUDER_BASE_Z),
  this._level)`, где `OCCLUDER_BASE_Z = 5` — новая константа ПАРТА (порядок
  отрисовки живёт в партах, решение 5.3 предыдущего этапа). 5 — выше танка
  (`TANK_BASE_Z = 3`), дыма (4), бомбы и эффектов (2), следов (1) и ниже
  шага уровней (`levelZStride = 100`). Номер слоя из карты сохранить в
  `this._layer` (сейчас он читается прямо в `zIndex`, `:121`).
- Клин рампы остаётся в `this` (см. шаг 2).
- `_updateStatic` (`:438`) обновляет и перекрыватель: параллакс его срезов
  (тот же цикл), `alpha`/`tint` и фильтр «дыры».
- `destroy` (`:635`): снять перекрыватель со сцены (`this.parent
  ?.removeChild`), уничтожить `{ children: true, texture: false,
  textureSource: false }` (текстура общая со слоем!), уничтожить его фильтр
  «дыры», обнулить ссылку. Порядок как у остальных: сначала со сцены,
  потом ресурсы.

Перекрытие возникает ровно там, где стена стоит МЕЖДУ камерой и танком, —
то есть оно физически верное: танк за стеной и должен быть за стеной.

### 4.2 «Дыра» вокруг игрока на своём уровне

Чтобы свой танк не пропадал за высоким зданием (`terraces` даёт стенам
`volumes: { 2: 1.0 }` — целый уровень):

- `src/client/seeThrough.js`: рядом с `seeThroughAlpha` (`:35`) добавить
  `volumeAlpha({ viewLevel, viewX, viewY, level, x, y, cfg })` — та же
  радиальная кривая (`innerRadius`/`smoothStep` переиспользуются), но
  порог другой: гаснет объём уровня `level >= viewLevel` (у обычных
  сущностей — строго `>`). В режиме `'layer'` объём СВОЕГО уровня не
  гасится вовсе (гасить весь слой стен, пока игрок на земле, — не
  вариант); объём уровней выше ведёт себя как сегодня.
- `src/client/levelView.js`: метод `volumeAlphaFor(level, x, y)` поверх
  новой функции — формула прозрачности обязана остаться одна на всех.
- `Map._updateSeeThrough` (`:491`): сейчас `_updateStatic` зовёт его только
  при `this._level >= 1` (`:439`). Условие расширяется: слой с
  перекрывателем считает прозрачность на любом уровне. Сила перехода у
  перекрывателя своя (`this._occluderHoleStrength`, то же сглаживание

## Шаг 6. Единая проекция высоты для всей динамики

Правило: объект на высоте `z` (в уровнях) рисуется смещённым
`offsetPoint(x, y, camera, z * shear)` И увеличенным в `(1 + z * shear)`
раз — ровно так же, как плита, на которой он стоит (`applyParallax`
делает и то, и другое одним трансформом). Отдельного `zScaleGain` больше
нет.

1. `src/config/render.js`: удалить `parallax.zScaleGain` (`:52`), в шапке
   блока записать правило одной строкой.
2. `src/client/parts/Tank.js:259`: `const zScale = 1 + this._z *
   parallaxConfig.shear;`. Масштаб получают `body`, `gun` И `wreck`
   (сейчас обломки остаются при `_scaleFactor`, `:168`).
3. `src/client/parts/Smoke.js`: добавить `renderer` в зависимости, в
   `onRender` (`:132`) — `applyParallax(this, cameraCenter(this.parent,
   this._renderer), z * shear, 1)`. Частицы живут в мировых координатах,
   контейнер единичный, поэтому трансформ контейнера даёт им ровно
   `offsetPoint`. Высота берётся из `M1_Z` (уже читается в `update`) —
   хранить в `this._z`. Записать известное упрощение: облако смещается по
   ТЕКУЩЕЙ высоте танка, поэтому уже отпущенные частицы едут вместе с ним;
   для дыма это незаметно (жизнь частицы < 2 с).
4. `src/client/parts/Bomb.js`: у бомбы позиция лежит на самом контейнере
   (`this.x/this.y`, `:38-39`), поэтому `applyParallax` к ней применять
   нельзя — считать `offsetPoint` от сохранённых `_worldX/_worldY` и
   ставить `this.position` + `this.scale.set(1 + k)` в существующем
   `onRender` (`:31`). Высоты в строке `w2` нет — `k = level * shear`.
5. Эффекты: `src/client/parts/effects/*/…Controller.js` (`ShotEffect`,
   `ExplosionEffect`) — там, где сейчас считается только
   `alphaFor`/`tintFor`, добавить тот же сдвиг и масштаб по `level`.
6. `src/config/client.js`: `renderer` в `componentDependencies` (`:145`)
   получает `'Smoke'`, `'Bomb'`, `'ShotEffect'`, `'ExplosionEffect'`;
   комментарий рядом обновить.
7. `Tracks` уже проецируется контейнером уровня
   (`Tracks.js:304`) — не трогать.

**Тесты**: `tests/client/parts/Tank.test.js` — масштаб корпуса на уровне 1
равен `1 + shear` от наземного; `tests/client/parts/Bomb.test.js` и

## Приёмка пользователем: пять замечаний и что по ним сделано

Пользователь проверил игру и нашёл пять дефектов. Разбор и правки:

1. **Стены потеряли объём, гаснут около танка.** Причина: перекрыватель
   открывал «дыру» всегда, когда `levelView.level >= this._level`, а у
   наземных стен это истинно ВСЕГДА — объём круга радиусом 260 вокруг
   игрока стоял на `minAlpha` 0.12. Заодно вскрылась обратная ошибка: у
   слоя ВЫШЕ игрока (перила моста) условие давало «не гасить», то есть
   возвращался дефект Д4. Правка: объём чужого уровня над игроком гаснет,
   как и раньше, вместе со своим слоем, а объём СВОЕГО уровня — только
   когда действительно накрывает танк (`Map._volumeHidesPlayer`: по
   нарисованной точке игрока обратной формулой среза считается исходная
   клетка, и проверяется, есть ли в ней тайл слоя). `volumeAlpha`
   /`volumeAlphaFor` удалены — порог больше не нужен.
2. **На широкую горку не заехать с подножия.** Воспроизведено тестом
   реплики `replica_drives_onto_a_wide_ramp_off_centre`
   (`core/src/client/predictor.rs`): танк, идущий по границе двух полос,
   встаёт на `x = 72.95` при кромке рампы 80. Причина ДВИЖКОВАЯ:
   `GameMap::create_ramp_guards` ставит борта каждому прогону, поэтому
   внутренние границы полос широкого блока огорожены на всю длину, и блок
   работает как набор жёлобов в тайл шириной. Правится только в E —
   вынесено в `stage_7.md` § 7.0.3 (одним релизом с остальными долгами);
   тест до публикации помечен `#[ignore]`.
3. **Падение при повторной смене карты на terraces** (`BindGroup.
   setResource`, `GlMeshAdaptor.execute`). Разбор жизненного цикла парта и
   движкового `applyMapData` (`removeMap` → `createMap`, обе синхронные)
   дырки не нашёл: каждое продолжение после `await` проверяет
   `this.destroyed` и само освобождает свою текстуру. Поэтому сделана
   защита от всего класса ошибки: перед освобождением общих источников
   `destroy` снимает ссылки на них у всех срезов (`texture = Texture.
   EMPTY`), и даже переживший уничтожение меш рисуется пустой текстурой, а
   не мёртвым источником. Если падение повторится — нужен номер кадра и
   карта до/после, чинить придётся по живой сцене.
4. **Дрожание танка под уровнями.** Правок не делалось: это ровно тот
   симптом, что описан в `stage_7.md` § 7.0.2 (реплика собирает стены
   поклеточно, хост — склеенными блоками; на касательном ударе об угол
   траектории расходятся, и реконсиляция дёргает танк). Пользователь
   уточнить место не смог — перепроверить после релиза движка.
5. **Юбка горки видна только с одной стороны.** Причина: UV юбки брались с
   кромки прогона, а дальняя кромка (`col1`/`row1`) — это уже следующая
   клетка, тайла рампы в ней нет, и грань растягивала прозрачные пиксели.
   Правка: выборка юбки сдвинута внутрь прогона на пиксель грида
   (`uvInset`), тест проверяет, что все UV юбки лежат строго внутри
   прямоугольника прогона.

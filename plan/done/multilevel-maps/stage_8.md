## 8.1 Тайлы ✅ выполнен

Отдельный тайл-лист рисовать не нужно — на первую итерацию берём кадры из
уже лежащего в репозитории листа. Открыть `assets/img/tiles.png`
(544 × 288, сетка 32 × 32 ⇒ 17 колонок × 9 строк) и подобрать глазами
шесть различимых кадров, назначив им смысл:

| Индекс | Смысл | Уровень |
| --- | --- | --- |
| 0 | асфальт / земля | 0 (пол) |
| 1 | стена здания | 0 (`physicsStatic`) |
| 2 | плита моста | 1 (`floor`) |
| 3 | перила моста | 1 (`floor` + `walls`) |
| 4 | рампа, подъём на север | 0 (пол, `ramps`) |
| 5 | рампа, подъём на юг | 0 (пол, `ramps`) |

Записать выбранные координаты кадров в комментарии карты — чтобы правку
художника потом было куда приземлить. Полноценный тайл-лист города —
отдельная задача, в этот план не входит (зафиксировать в
`plan/README.md` в списке «после первой итерации»).

## 8.2 `src/data/maps/overpass.js` — демо-карта ✅ выполнен

Требования к карте (она же — фикстура ручной проверки):

* размер 80 × 60 тайлов, `step: 32`, `scale: 0.4`;
* по периметру — стены уровня 0;
* **сквозная эстакада** по горизонтали через середину: полоса плиты
  шириной 3 тайла, с перилами по обеим длинным сторонам на большей части
  длины;
* **два разрыва в перилах** (по одному с каждой стороны) — те самые
  обрывы, с которых падают и через которые простреливают снизу;
* **две рампы** на концах эстакады: одна с подъёмом на север, другая на юг,
  длиной 3 тайла и шириной 3 тайла;
* **проезд под мостом** свободен: под плитой на уровне 0 стоит только пол;
* `physicsDynamic`: 2 ящика на уровне 0 под мостом и 2 на уровне 1 на
  плите — это проверяет `level` динамики;
* `respawns`: по 10 точек на команду. У каждой команды 8 точек на земле
  (без 4-го элемента — уровень выведется как 0) и 2 на плите с явным
  `[x, y, angle, 1]` — так одновременно проверяются оба пути назначения
  уровня;
* **ни одна наземная точка респауна не стоит под плитой** — иначе выведенный
  уровень окажется 1. Точки под мостом задавать только с явным `0`.

Скелет:

```js
export default {
  setId: 'c1',
  scale: 0.4,
  step: 32,

  spriteSheet: {
    img: 'tiles.png',
    frames: [
      // [x, y, w, h] — координаты выбраны по 8.1
    ],
  },

  // рендер-слои уровня 0
  layers: {
    1: [0, 4, 5], // пол и рампы под танком
    2: [1],       // стены
  },

  physicsStatic: [1],

  levels: {
    1: {
      map: /* грид уровня 1: 0 — пустота, 2 — плита, 3 — перила */,
      floor: [2, 3],
      walls: [3],
      layers: {
        1: [2], // плита моста (zIndex 101)
        4: [3], // перила (zIndex 104)
      },
    },
  },

  ramps: [
    { tile: 4, dir: 'north', from: 0, to: 1 },
    { tile: 5, dir: 'south', from: 0, to: 1 },
  ],

  physicsDynamic: [ /* level: 0 и level: 1 */ ],

  respawns: {
    team1: [ /* 8 наземных [x, y, 0] + 2 мостовых [x, y, 0, 1] */ ],
    team2: [ /* зеркально, angle 180 */ ],
  },

  map: /* грид уровня 0 */,
};
```

Гриды строить функцией-конструктором (как в `canopy.js`) — вручную
80 × 60 не поддерживается.

Зарегистрировать в `src/data/maps/index.js`:

```js
import overpass from './overpass.js';
...
  overpass,
```

> **Не менять `currentMap`** в `src/config/game.js` — дефолтом остаётся
> `pool mini`. Демо-карта выбирается в лобби/`room.map`.

## 8.4 Сценарии отладки ✅ выполнен

Каталог `tests/scenarios/`. Формат — как в существующих файлах.

### `bridge.json`

Один игрок, карта `overpass`. Таймлайн: заехать на рампу, проехать по
мосту, съехать по второй рампе.
`dumpTicks` на середине рампы, на плите и после спуска. Ожидание: в дампах
`level` меняется 0 → 1 → 0.
`divergence.thresholds` — те же, что в `movement.json`.

### `fall.json`

Один игрок: заезд на мост, проезд к разрыву в перилах, съезд в пустоту.
`dumpTicks` до срыва, в середине падения и после приземления.
Проверяет: `level` 1 → 0, здоровье уменьшилось на `fallDamage`.

### `crosslevel.json`

Два игрока: p1 на мосту, p2 под мостом. p1 стреляет вдоль моста и за
кромку; p2 стреляет вверх из-под кромки и из глубины под плитой.
`unusedSnapshotKeys` — только `c2`.

### `bots_bridge.json`

Один игрок + `/bot 2` через `chat`-операцию; карта `overpass`, длинный
прогон (`ticks: 1800`). Проверяет, что боты пользуются рампой и не
застревают (инварианты 10/11 раннера).

Прогон: `npm run sim:scenarios` (он подхватывает все файлы каталога) и
поштучно `npm run sim -- --scenario tests/scenarios/bridge.json`.

## 8.7 `requires: ['map.layers']` ✅ выполнен

Игра без слоёв в движке не запустится корректно — плагин обязан это
объявить.

* `src/host/index.js` и `src/client/index.js`: добавить в объект плагина
  ```js
  // без слоёных карт движка (`levels`/`ramps` в MAP_DATA, маски уровней в
  // физике) карта overpass соберётся без второго уровня и без единой
  // ошибки — поэтому возможность объявлена жёстким требованием
  requires: ['map.layers'],
  ```
* `scripts/build-game-manifest.js`: положить `requires` в манифест, взяв
  его из одного источника (импортировать из `src/host/index.js`, а не
  дублировать литерал).
* `scripts/check-pack.js`: если он валидирует манифест — добавить проверку
  наличия `requires`.

## 8.10 Релиз ✅ выполнен — vimp-engine-core 0.10.0 / vimp-engine 0.29.0 опубликованы, танки вышли 0.17.0

1. **Крейт движка.** В `E`: `packages/engine/core/CHANGELOG.md` —
   `## [Unreleased]` → `## [0.10.0] - YYYY-MM-DD`, открыть пустой
   `## [Unreleased]`. Бампнуть `version` в `packages/engine/core/Cargo.toml`.
   Опубликовать крейт (процедура — `docs/en/publishing.md` движка).
2. **npm-пакет движка.** В `E`: обновить зависимость на новую версию
   крейта, проставить реальную версию в `capabilities.js`
   (`{ value: 'map.layers', since: '<эта версия>' }`), прогнать
   `npm run release` движка (он и датирует журнал, и бампает версию по
   заголовкам).
3. **Танки.** В `T`:
   * снять `[patch.crates-io]` из `Cargo.toml`;
   * `core/Cargo.toml`: `vimp-engine-core = "<новая версия>"`;
   * `package.json`: `devDependencies.vimp-engine` → `^<новая версия>`;
   * `npm run core:build && npm run core:test && npx eslint . &&
     npm test -- --silent && npm run build && npm run sim:scenarios &&
     npx vimp-contract --strict`;
   * релиз танков — вручную (в этом репозитории нет `npm run release`):
     тем же коммитом поднять `version` в `package.json`, версию в
     `core/Cargo.toml`, обновить `Cargo.lock`/`package-lock.json` и
     переименовать `## [Unreleased]` в `## [X.Y.Z] - YYYY-MM-DD`, открыв
     пустой `## [Unreleased]` выше. Версия — **minor** (новая
     функциональность, ничего ранее принимавшегося не отвергается).
4. Вернуть `src/standalone.js` на `room: { map: 'pool mini' }`.

> **Коммиты не делать.** По правилам репозитория все изменения остаются в
> рабочем дереве; пользователь коммитит и публикует сам. Релизные шаги
> выше — подготовка файлов, а не `git commit`/`npm publish`.

Плюс глазами в браузере (`npm run dev`, карта `overpass`):

- [ ] заезд на мост по обеим рампам, спуск обратно;
- [ ] проезд под мостом — плита становится полупрозрачной;
- [ ] танк на мосту рисуется поверх плиты, под мостом — под ней;
- [ ] выстрел с моста за кромку попадает по танку на земле;
- [ ] выстрел с моста вдоль плиты не задевает танк внизу;
- [ ] выстрел снизу по танку у открытой кромки попадает, по танку за
      перилами — нет;
- [ ] бомба на мосту не задевает танк ровно под ней и наоборот;
- [ ] падение с разрыва в перилах: анимация снижения, урон, шейк;
- [ ] боты заезжают на мост и стреляют осмысленно;
- [ ] `pool mini` выглядит и играется ровно как до всей работы.

# План: карта «downtown» — ночной город с интерактивной средой

Итоговый поэтапный план. Цель — новая многоуровневая городская карта с физикой поверхностей,
разрушаемым окружением, ночным освещением и анимированными элементами. Существующие карты не
меняются; все механики доступны любой карте через новые необязательные поля.

### Правила, обязательные на каждом этапе

1. **Никаких коммитов** (`git commit` запрещён): изменения остаются в рабочем дереве. Релизные скрипты,
   которые коммитят, запускает пользователь.
2. **Документация**: любое функциональное изменение обновляет парные страницы `docs/en/` и `docs/ru/`
   (таблица «область → страница» в `CLAUDE.md` плагина). В движке — его собственные `docs/en|ru` и `docs/ai/`.
3. **CHANGELOG.md** (английский, Keep a Changelog) обновляется в том же изменении, в разделе `## [Unreleased]`.
   Тесты, рефакторинг и `docs/` в журнал не пишутся. Изменение формата кадра или конфигурации попадает
   в `### ⚠️ Breaking` вместе с `### Migration`.
4. **Проверки в конце каждого этапа** (тихие флаги):
   ```bash
   npx eslint .
   npm test -- --silent
   npm run core:test          # после любой правки core/ или src/data/models.js
   npm run core:build         # перед тестами, которым нужен core/pkg-node, и перед npm run build
   npm run build              # когда меняются карты, ассеты или манифест
   npx vimp-contract          # когда меняются карты, конфиг, снапшот или части
   npm run sim:scenarios      # после npm run build, когда меняются физика или карты
   ```
5. **Паритет движения**: формулы движения живут только в `core/src/motion.rs` (и новом `core/src/surface.rs`) и
   вызываются обеими сторонами — `Tank::update` (хост, `core/src/tank.rs`) и `Predictor::step_inner`
   (`core/src/client/predictor.rs`). Любая правка движения закрывается тестами `client::predictor::parity`.
   Если паритет не сходится, фича не выпускается.
6. **Нейтральный путь бит-в-бит**: без поверхностей, пропов и освещения поведение и кадр должны остаться прежними
   (кроме нового байта `state` в строке `c1/c2`, который вводится явно как breaking).
7. **Код**: ES-модули, camelCase/PascalCase/UPPER_SNAKE_CASE, без двух заглавных подряд, `===`, только `let`/`const`,
   обязательные фигурные скобки. `src/host/` должен оставаться Worker-safe. Комментарии в коде — на русском
   (как в текущем коде).
8. **Части PixiJS**: колбэк `onRender` тестируется на *регистрацию* (`part._onRender`), а не только вызовом тела.
   Анимация, завязанная на время, шагает один раз за тик (`Ticker.shared` или защита по `Ticker.shared.lastTime`),
   потому что движок может рендерить сцену несколько раз за тик.

### Архитектурные факты, найденные при исследовании (на них опирается план)

- **Строки динамических тел карты (`c1`/`c2`, `indexedNoNull8`) собирает движок**
  (`GameMap::dynamic_map_data`, `map.rs` ≈1766), а не игра. Раскладка фиксирована: `[x, y, angle, z?, level?, vx?, vy?, angvel?]`.
  Маркера удаления нет; тело, пропавшее из мира, молча перестаёт давать строку, и спрайт на клиенте замирает.
- **Игра не имеет доступа к телам карты**: `SimCtx.map` — `&Option<GameMap>` (только чтение), хэндлы тел приватны
  (`dynamic_bodies`, `map.rs` ≈1473). При этом `SimCtx.world` — `&mut`.
- **Игровое ядро не видит сырой JSON карты**: `EngineSim::load_map` (`game.rs` ≈86) разбирает только `MapConfig`
  (без `deny_unknown_fields`, лишние поля молча отбрасываются). Хука «карта загружена» нет — сейчас `TanksSim`
  отслеживает смену карты по отпечатку (`sync_levels`, `tanks.rs` ≈811). На плоской карте `TanksSim.levels == None`.
- **Клиент движка передаёт полям карты белый список**: `applyMapData` (`client/main.js` ≈577–600) собирает JSON для
  `ClientCore.set_map` из `map, step, scale, setId, physicsStatic, physicsDynamic, levels, ramps, levelHeight`
  (так же в `devtools/VirtualClient.js` ≈196). Статические части `s0..sN` получают
  `{type:'static', spriteSheet, map, step, layer, tiles, level, solid, floor, volume, levelHeight, ramps, physicsStatic, scale}`
  (`main.js` ≈651–676). Динамические `d{i}` получают `{...item, type:'dynamic', scale}` — лишние ключи `physicsDynamic[i]` доходят.
- Хост отправляет клиенту полный объект карты (`RoundManager.js` ≈115/217); **в начале каждого раунда** вызывается
  `_game.createMap(...)` (`RoundManager.js` ≈314) → `load_map`, то есть тела карты пересоздаются.
- **Порядок фиксированного шага движка**: `map.step_dynamic_levels` → `sim.on_fixed_step` → `world.step_with_events` →
  `sim.on_contacts` (только `CollisionEvent::Started`; канал сил создаётся и выбрасывается).
- **Взрыв бомбы** — `TanksSim::detonate` (`tanks.rs` ≈1186) привязан к бомбе и оружию; урон — `apply_damage` (≈1285).
  **Баг**: для тел карты расстояние и точка импульса берутся от `body.translation()`, то есть от угла тела, а не от центра.
- **Уклон рампы (`grade`)** — ближайший прецедент модификатора движения: `level::step_level` заполняет `LevelState.slope_vec`
  на обеих сторонах до ввода, `LevelState` — `Copy`, пишется в историю предиктора каждый шаг и откатывается при
  реконсиляции (`predictor.rs` ≈1080/1085). Поле, добавленное в `LevelState`, откатывается бесплатно.
- **Паритетные тесты** — `mod parity` в `predictor.rs` (≈3468): `simulate` (без карты, 6 сценариев) и `simulate_on_map`
  (≈3586, с картой и `Pose`); сравнение — `expect_close` (≈3706) и `expect_scenario_thresholds` (≈3641).
- **Хост-танк**: скорость меняется только импульсами (`apply_impulse`, `apply_torque_impulse`), демпфирование задаётся
  один раз при спавне. Дополнительное сопротивление выражается как Δv-импульс (так же, как `lateral_dv`), без изменения
  демпфирования Rapier. Реплика прибавляет тот же Δv к `vx/vy` до `resolve_world` и `integrate`.
- **Стадия отрисовки 2.5D**: `zIndex = base + 100·level` (`src/client/levelZ.js`); база: `Tracks` 1, эффекты/бомбы 2,
  `Tank` 3, дым/взрыв 4, окклюдер объёмов 5. Проекция — `offsetPoint`/`applyParallax` (`src/client/parallax.js`),
  прозрачность над игроком — `levelView.alphaFor`, фильтр дыры — `src/client/parts/map/holeOverlay.js`.
  Сцена сортирует детей по `zIndex`; часть может добавлять собственных «соседей» на сцену
  (тень танка — `Tank.js` ≈555; окклюдер — `MapLayer.js` ≈216) и обязана сама их удалять.
- **Лимит**: не более 255 динамических тел на карту (индекс `u8`). Обломки не создаются новыми телами.

### Глоссарий

- **Поверхность** — свойство клетки сетки конкретного уровня (песок, грязь, вода, масло, конвейер, бустер).
- **Проп** — динамическое тело карты с игровым типом (`fence`, `crate`, `barrel`).
- **Состояние тела** — байт `state` в строке `c1/c2`: `0` — цел, `1` — повреждён, `2` — разрушен (обломки или копоть).
- **Карта освещённости** — `RenderTexture` уровня: окружающая темнота плюс аддитивные источники; накладывается
  на сцену режимом `multiply`.
- **Эмиссивный слой** — спрайты, которые светятся сами (неон, головы фонарей, блики фар) и рисуются поверх затемнения.

## Риски

1. **Паритет** (поверхности, особенно масло и разворот гусеницами): закрывается сценариями `mod parity`; неудача
   блокирует этап.
2. **Движок**: этап 0 меняет `SimCtx` и раскладку строки тел; обратная совместимость держится за счёт того, что всё
   включается по объявлению (роль `state`, поле `game`). Требуется релиз движка до этапа 1.
3. **Двойное затемнение между уровнями** (этап 7): решается масками этажей в картах освещённости верхних уровней.
4. **Прыжок с бустера**: бустер увеличивает горизонтальную дальность прыжка с рампы; площадки приземления
   проверяются в `sim` и вручную (этап 9).
5. **Предсказание разрушения**: локальный танк ещё ~100 мс упирается в забор, уже сломанный на хосте. Это осознанно
   допустимо и документируется.

# Этап 4. Клиентская визуализация поверхностей ✅ выполнен

**Репозиторий:** `vimp-tanks`. **Зависит от:** этапов 1–3.
**Перед началом:** `plan/night-city/README.md` → «Общий контекст»; `docs/en/architecture.md` → «The client side»,
«Texture and particle lifecycle»; `docs/en/extending.md` → «New client entity (part)».

## Цель

Игрок видит и слышит, по чему едет: пыль на песке, комья грязи, брызги в воде, блеск и отсутствие следов на масле,
вспышка бустера. Поверхность под точкой клиент берёт **из ядра** (одна таблица с физикой), без копии в JS.

## 4.1 ABI и сервис `surfaces`

1. `core/src/lib.rs`, `ClientCore` (рукописный метод рядом с `ramp_runs`):
   `surface_at(x: f32, y: f32, level: u8) -> i32` — индекс типа или `-1` (нет карты / нейтрально);
   `surface_types() -> String` — JSON-массив имён типов в порядке индексов;
   `surface_dir_at(x: f32, y: f32, level: u8) -> i32` — направление стрелки (`0..3`: N/S/W/E как у рамп) или `-1`.
2. `src/client/index.js`, `hooks.services(core)`: сервис
   `surfaces = { kindAt(x, y, level) -> string|null, dirAt(x, y, level) -> [dx, dy]|null }`
   (кэш имён из `surface_types()`, сбрасывается при `set_map`; `dirAt` переводит индекс `surface_dir_at` в единичный
   вектор по таблице N/S/W/E). `surface_types()` направлений не содержит — стрелка берётся только из `dirAt`. Добавить `'surfaces'` в `ClientPlugin.serviceNames`.
3. `src/config/client.js` → `componentDependencies.surfaces: ['Dust', 'Tracks', 'Tank']`.

## 4.2 Реакции частей

1. `src/client/parts/Dust.js` — источник по типу поверхности под танком (центр корпуса, уровень — отрисовочный):
   - `sand`: частая светло-жёлтая пыль, пропорционально скорости;
   - `mud`: тёмные тяжёлые комья (короче жизнь, больше размер);
   - `water`: брызги (голубой тинт, всплеск по сторонам гусениц; разовый всплеск при въезде со скоростью);
   - `oil`: без пыли;
   - `boost`: разовая вспышка-хвост при срабатывании. Признак — то же правило въезда, что в ядре (этап 2.3.5):
     центр танка на клетке `boost` с направлением `dir`, клетка предыдущего кадра — **не** бустер с тем же `dir`
     (вне карты — «не бустер»), проекция скорости на стрелку `≥ minEntrySpeed` (стрелка — `surfaces.dirAt`).
     Переход между клетками одной плиты 2×3 вспышки не даёт.
     **Первый кадр без предыдущей клетки** — вспышки нет. Признаки — только то, что часть видит в своих данных:
     переход `condition` 0 → жив (респаун), первое появление танка, скачок позиции больше чем на 2 клетки за кадр,
     смена карты. Флаг сброса камеры частям недоступен: движок забирает его в модель холста
     (`CanvasManager.updateCoords([x, y, cameraReset, shakeData])`, `components/controller/CanvasManager.js:18`),
     и опираться на него нельзя. Скачок позиции покрывает телепорт и своего, и чужого танка.
     В этих случаях часть только запоминает текущую клетку. Тест: респаун прямо на плите бустера — без вспышки.
     Скачок скорости как признак не годится: у чужих танков скорость приходит интерполированной (`lerp`) и
     размазана на несколько кадров. Порог `minEntrySpeed` — в `render.js → surfaceFx.boostMinSpeed`
     (визуальная копия; расхождение с ядром даёт лишь лишнюю или пропущенную вспышку).
   Параметры — новый блок `surfaceFx` в `src/config/render.js` (цвета, частоты, пороги). Частицы — существующий
   `ParticlePool`/`ParticleContainer`.
2. `src/client/parts/tracks/Tracks.js` (часть регистрируется через `parts/tracks/index.js`): `oil` — тёмные глянцевые следы с повышенной альфой и длинной жизнью; `water` — без следов;
   `mud` — более тёмные следы.
3. `src/client/parts/Tank.js`: необязательный звуковой отклик на грязи (повышенный `engineLoad` уже приходит с хоста).
   Отдельный звук не добавляется.
4. Звуки брызг и бустера: новых исходников нет. В `src/config/sounds.js` можно завести `splash`/`boost` с `file`,
   указывающим на существующие файлы (`hit`, `explosion`), или отложить звук. Решение записать в `configuration.md`.

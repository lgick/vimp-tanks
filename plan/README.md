# Многоуровневые карты (2.5D, стиль GTA 2) — мастер-план

Два уровня: **Земля (level 0)** и **Мост/Эстакада (level 1)**. Переходы —
направленные рампы. Мосты имеют опциональные перила; без перил край моста —
обрыв, с которого танк падает вниз. Стрельба и взрывы работают между
уровнями по явным правилам. Боты умеют пользоваться мостами.

## Два репозитория

| Обозначение | Путь | Что публикуется |
| --- | --- | --- |
| **E** | `/Users/dmitry/Sites/my/vimp` | крейт `vimp-engine-core` (crates.io) + npm `vimp-engine` |
| **T** | `/Users/dmitry/Sites/my/vimp-tanks` | npm `@vimp-games/tanks` |

Формат карты, статическая геометрия, нав-граф ботов и транспорт `MAP_DATA`
принадлежат **движку**, а не игре. Поэтому слои реализуются как **фича
движка** (решение пользователя), а игра пользуется ими через новую
возможность `map.layers` (`GameManifest.requires`).

## Принятые решения (не пересматривать без явной команды)

1. **Слои — фича движка.** `MapConfig`/`GameMap`/`NavigationSystem` учат
   слои; игра получает готовую геометрию. Новая capability `map.layers`.
2. **Формат карты аддитивен.** Поля `map` / `physicsStatic` / `layers`
   остаются уровнем 0. Второй уровень приходит новым необязательным полем
   `levels`, переходы — полем `ramps`. Карта без них — ровно как сегодня,
   бит-в-бит. Существующие `canopy` / `garden` / `pool mini` не трогаем.
3. **Формат кадра НЕ меняется.** `PLAYER_STATE_LEN` остаётся `8`, версия
   снапшота не растёт. `level`/`z` едут в игровом блоке `m1`
   (`src/config/snapshot.js` — данные игры), а клиентский предиктор
   вычисляет их сам по тем же правилам и тем же гридам.
4. **`ENGINE_API_VERSION` не бумпается** (он заморожен на 4). Все правки ABI
   ядра — только append-only (новый метод `set_actor_level`).
5. **Луч L0 → L1**: луч всегда идёт на уровне стрелка; в *первом* тайле с
   плитой, в который он вошёл, он может поразить танк уровня 1, если этот
   тайл — не тайл перил. Дальше плита экранирует всё.
6. **Луч L1 → L0**: пока луч над плитой — бьёт только цели уровня 1; на
   первом тайле без плиты он «падает» на уровень 0 и дальше бьёт только
   цели уровня 0.
7. **Падение с обрыва**: состояние `Falling` длиной `fallTime` (0.35 c),
   управление заблокировано, коллизий нет, при приземлении — фиксированный
   `fallDamage` (15) и событие `Death{victim, killer: victim}`, если добило.
8. **Взрыв** поражает только цели своего уровня — плита моста экранирует.

## После первой итерации (сознательно вне плана)

Не делать в рамках этих восьми этапов; список нужен, чтобы отличать
«отложено» от «забыто».

* **Конструктор карт** — веб-редактор с вкладками «Слой 0» / «Слой 1» и
  кистью рамп. Формат под него уже спроектирован (плоские гриды одинаковой
  размерности, тайлы с ролями в `physicsStatic`/`floor`/`walls`/`ramps`).
* **Собственный тайл-лист города** — сейчас демо-карта берёт кадры из
  существующего `assets/img/tiles.png`.
* **Радиальная маска прозрачности** вокруг игрока вместо alpha на весь
  слой моста.
* **Трассер, ломающийся на кромке плиты** — сейчас он рисуется целиком на
  уровне конца луча.
* **Тень танка** отдельным спрайтом вместо смещения/масштаба по `z`.
* **Маркер уровня на радаре** для чужих танков.
* **Гранаты** (бросок с дугой и падением вниз) — сегодняшняя бомба
  статична и просто помнит свой уровень.
* **Больше двух уровней** — `MAX_LEVELS = 2` зашит осознанно.

## Глоссарий

| Термин | Значение |
| --- | --- |
| **Уровень (level)** | `0` — земля, `1` — эстакада. `u8`. |
| **z** | Непрерывная высота `0.0..1.0` для визуала: подъём по рампе, падение. `f32`. |
| **Плита (slab / floor)** | Тайл уровня 1, по которому можно ездить. Непрозрачен для луча снизу. |
| **Перила (railing / wall)** | Тайл уровня 1, блокирующий движение и луч на уровне 1; закрывает край от выстрела снизу. |
| **Обрыв (ledge)** | Граница плиты без перил. С него падают. |
| **Рампа (ramp)** | Направленный прогон тайлов уровня 0, по которому z меняется 0 → 1. |
| **Прогон рампы (RampRun)** | Максимальная непрерывная последовательность тайлов рампы вдоль её оси в одной строке/колонке. |

# Этап 8. Анимированные элементы карты ✅ выполнен

**Репозиторий:** `vimp-tanks`. **Зависит от:** этапов 1 и 7 (эмиссивный слой и источники света для неона).
**Перед началом:** `plan/night-city/README.md` → «Общий контекст»; `docs/en/architecture.md` → «The client side»,
«Texture and particle lifecycle»; `plan/night-city/stage_7.md` → разделы 7.1 и 7.4.

## Цель

Анимируются вода, конвейеры (шевроны синхронно с физикой ленты), вентиляторы на крышах, неоновые вывески
(пульс, мерцание, сбои). Всё — только на клиенте, хост ничего не знает. Статичный город запекается как раньше;
анимированные тайлы в запекание не попадают и рисуются лёгким батчем.

## 8.1 Поля карты

```js
game: {
  animatedTiles: {
    // id тайла → описание; действует на всех уровнях, где тайл встречается
    45: { kind: 'frames', frames: [45, 60, 61, 62], speed: 60 },   // конвейер: fps вычисляется из speed
    43: { kind: 'frames', frames: [43, 63, 64, 65], fps: 4 },      // вода
  },
  signs: [
    { cell: [40, 20], level: 1, layer: 1, text: 'HOTEL', color: 0xff3ad0, size: 18, angle: 0,
      flicker: { pulse: 0.15, dropouts: 0.2 }, light: { radius: 80, intensity: 0.7 } },
  ],
  decals: [
    { cell: [10, 8], level: 1, layer: 1, frame: 70, kind: 'rotate', rps: 1.5 },  // вентилятор на крыше
  ],
}
```

- `frames` — индексы кадров `spriteSheet.frames`. Ровно одно из `fps` и `speed`: `fps` — для обычной анимации,
  `speed` — для конвейера, и тогда `fps` **вычисляется**, а не задаётся (заданы оба — ошибка проверки в
  `tests/config/game.test.js`). `speed` (ед./с) обязан совпадать с `belt` типа поверхности тайла:
  `fps = speed · кадров_на_тайл / (step · scale)` (на клиенте `step` не масштабирован, `scale` лежит отдельно).
  Кадры — шевроны со сдвигом на 1/N тайла, **уже нарисованные в направлении ленты**: у каждого направления свой тайл
  и свои кадры (`CONVEYOR_E`, `CONVEYOR_W`), спрайт не поворачивается. Поля `scrollDir` нет — направление задаёт
  `dir` поверхности, повторный поворот развернул бы стрелку дважды.
- `signs`/`decals` строит **та часть `MapLayer`, чьи `(level, layer)` совпадают** — ровно один владелец на элемент.
- Вентиляторы на крышах ставятся на плиты крыш уровня ≥ 1 (слой уровня), а не на верх экструзии объёмов.
  Это ограничение автора карты.

## 8.2 Рефакторинг `MapLayer` (подготовка)

1. Ввести корневой контейнер слоя `layerRoot` внутри части: в нём `mapSprite` и новый `animated` контейнер.
   `applyParallax` (`MapLayer.js` ≈167–210) и фильтр дыры (`holeOverlay.apply`) применяются к `layerRoot`, а не к
   `mapSprite`, чтобы анимированные спрайты двигались и прозрачились вместе со слоем.
   Слайсы объёмов не меняются.
2. `bakeTileLayer.js` (≈14–76): тайлы из `animatedTiles` исключаются из запекания (фильтр по `tiles`).
3. Обновить `tests/client/parts/map/MapLayer.test.js` и `holeOverlay.test.js` под новую цель фильтра.
   Поведение без `game` — идентично (тест на снимок структуры).

## 8.3 Анимированные тайлы (`src/client/parts/map/animatedTiles.js`)

- `buildAnimatedTiles(data, sheet, defs) -> { container, groups }`: по одной `Sprite` на клетку слоя с анимированным тайлом.
  Текстуры из того же `Spritesheet`, что и запекание, поэтому один источник и один батч. `cullable = true`.
- Группы по описанию: все спрайты группы разделяют номер кадра, так что обновление — один проход по группе.
- `kind: 'frames'` — смена текстуры по общему времени; спрайты не поворачиваются (направление нарисовано в кадрах).
- Время — общий часовой модуль `src/client/animationClock.js` (`Ticker.shared`, одно приращение на тик; секунды с запуска).
  Все карты синхронны.
- Не освобождать текстуры листа (`destroy({ texture: false, textureSource: false })`).

## 8.4 Неоновые вывески

1. Бейкер `neonSignTexture` не подходит: текстов много и они из карты. Поэтому кэш
   `src/client/parts/map/neonCache.js`: `getNeonTextures(renderer, { text, color, size })` → `{ core, glow }`.
   Текстура `core` — `Text` (жирный моноширинный шрифт, белый) + `generateTexture`; `glow` — копия с `BlurFilter`
   по правилам `blurMargin` (`extending.md`). Цвет задаётся `tint`. Кэш общий на сессию, освобождается при уничтожении
   последнего пользователя (счётчик ссылок внутри кэша, не `Assets.unload`).
   Счётчик обязателен ещё и из-за потери WebGL-контекста: движок при восстановлении уничтожает все части
   (см. этап 7, «Потеря WebGL-контекста»), счётчик падает до нуля, мёртвые текстуры освобождаются, и новые вывески
   запекаются заново. Кэш без счётчика отдал бы новым частям текстуры мёртвого контекста. Тест: `acquire → release all →
   acquire` генерирует текстуру заново.
2. `NeonSign` (`src/client/parts/map/NeonSign.js`): спрайты `glow` + `core`, аддитивные. Сначала
   `lighting.addEmissive(sprite, level)`; при ночи — дополнительно `lighting.addLight` цвета вывески.
   Если `addEmissive` вернул `false` (нет ночи **или** `lighting.enabled = false`), вывеска рисуется в `animated`
   контейнере слоя и источник света не создаётся. В `destroy()` вывеска снимает свой источник и эмиссив.
   Вывеска строится в асинхронном `_build` части, то есть **после** синхронного `acquireMap` в конструкторе
   `MapLayer` (этап 7.5.1). Поэтому на ночной карте `addEmissive` уже видит ночь. Строить вывески до `acquireMap`
   или в конструкторе раньше него нельзя: результат `false` фиксируется навсегда.
3. Мерцание — чистая функция `src/client/neonFlicker.js`: `brightness(t, seed, cfg)`; `seed` — хэш клетки.
   Составляющие: базовый пульс `1 − pulse·(0.5 + 0.5·sin)` и детерминированные «сбои» — короткие провалы по
   псевдослучайному расписанию (SplitMix32 от `seed` и номера окна времени). Сбой гасит `core` сильнее, чем `glow`.
   Никакого `Math.random`: одинаковая картина у всех клиентов и в тестах.

## 8.5 Декали (вентиляторы и прочее)

`src/client/parts/map/decals.js`: `kind: 'rotate'` — `rotation += rps · 2π · dt` по часам; `kind: 'frames'` — как тайлы.
Спрайт в `animated` контейнере слоя, в центре клетки.

## 8.6 Производительность

- `render.js → animations: { enabled: true, maxFps: 30 }`: смена кадров не чаще `maxFps`;
  `enabled: false` — кадр 0, без обновлений.
- Группы, чей контейнер целиком вне экрана, пропускают обновление (проверка bounds контейнера раз в тик).
- Все тайлы и декали одного слоя — одна текстура-источник, один батч; неон — аддитивный батч в эмиссивном слое.

## 8.7 Тесты

- `animationClock.test.js`: одно приращение на тик при многократном рендере.
- `animatedTiles.test.js`: спрайты только на клетках анимированных тайлов слоя; смена кадров по времени; расчёт `fps`
  конвейера из `speed`; спрайты не поворачиваются.
- `neonFlicker.test.js`: детерминированность, диапазон `[0, 1]`, сбои появляются с ожидаемой частотой.
- `NeonSign`/`decals`: владелец — только слой с совпадающими `(level, layer)`; снятие из освещения в `destroy`;
  при `addEmissive → false` вывеска остаётся в `animated` контейнере и видна.
- `bakeTileLayer`: анимированные тайлы исключены.
- `tests/config/game.test.js`: у каждого конвейерного тайла `animatedTiles[id].speed === surfaces.types[type].belt`;
  у каждого описания ровно одно из `fps`/`speed`;
  кадры существуют в `spriteSheet.frames`; `(level, layer)` вывесок и декалей существуют в `layers` уровня.

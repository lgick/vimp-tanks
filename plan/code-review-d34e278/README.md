## Контекст

Коммит `d34e278` делает выстрел `w1` «танковым». Появились новая дульная вспышка (огненный шар `muzzleFlash.ball`,
ударное кольцо `muzzleFlash.ring`), разрыв в точке попадания (`impactFlash`, клуб дыма `PuffEffect` /
`impactSmoke`, ночной блик `lighting.flash.hit`) и сужение хвоста трассера (`tracer.taper`). Коммит меняет и
баланс (`src/data/models.js`, `src/data/weapons.js`, `src/config/game.js`):
- танк вдвое медленнее: `maxForwardSpeed` 260 → 130, `maxReverseSpeed` −130 → −65;
- корпус и башня поворачиваются медленнее: `baseTurnTorqueFactor` 215 → 110, `gunRotationSpeed` 3.0 → 1.5;
- у `w1` кулдаун `fireRate` 0.01 → 0.3 с, импульс попадания `impulseMagnitude` 7500000 → 1500000;
- запал бомбы `w2.time` 300 → 1000 мс;
- плиты-бустеры перенастроены: `boostDv` 220 → 350, `boostSpeedFactor` 1.8 → 3.6;
- карта по умолчанию `currentMap` — `downtown`.

Все изменения коммита лежат в `CHANGELOG.md` под `## [Unreleased]`: релиз `0.22.14` (`b86e6c2`) вышел до
`d34e278`. Поэтому новые функции коммита (дым разрыва) ещё не выпущены, и их исправление в журнал не пишется. Баг
бустера (этап 2) старше коммита, коммит лишь спрятал его правкой теста, поэтому его исправление — запись
`### Fixed`.

## Замечания без правок (к сведению пользователя)

Эти пункты — решения баланса или известные упрощения. План их **не исправляет**. Исполнитель упоминает их в
итоговом отчёте (этап 7).

1. **Таран пропов при новом потолке скорости.** В `src/config/game.js → coreParams.props` осталось
   `fence.ramThreshold` 60, `crate.ramThreshold` 140, `barrel.ramThreshold` 150. Урон тарана считается как
   `(impact − ramThreshold) · ramDamagePerSpeed` (`core/src/tanks.rs`, `process_rams`). При потолке 130:
   - забор (hp 30, 0.5 за единицу) ломается только почти лобовым ударом на скорости от 120;
   - ящик и бочку тараном теперь не повредить совсем, разве что с разгона от бустера.

   Docs таран ящиков и бочек не обещают (`docs/*/gameplay.md → Destructible objects`), но пороги подбирались под
   260. Если таран нужен, пороги стоит уменьшить вдвое, как перенастроили бустер. Это решение пользователя; в
   `configuration.md` и CHANGELOG оно попадёт вместе с правкой.
2. **Боты на `downtown` за минуту не кладут бомб** (С1). Бомба — только вплотную (`core/src/bots/brain.rs`,
   `wants_bomb`: `distance < BOMB_RANGE_SHARE * bomb.radius`). Сценарий это только фиксирует; нужно ли подстроить
   поведение ботов, решает пользователь.
3. **Фикстуры Rust** (`flat_config_json()` в `core/tests/sim.rs`, `config_json()` в
   `core/src/client/predictor.rs`) описывают танк на 260. Parity-сьют сверяет хост и реплику на фикстуре, а не на
   игровых `models.js`. Игровые значения в Rust покрывает только JS-харнесс (`tests/core/core.test.js`).
4. **`npm run dev`** (`src/standalone.js`) по-прежнему стартует на `pool mini`, а `currentMap` теперь `downtown`.
   Docs описывают это верно (`getting-started.md`). Нужно ли совпадение — отдельное решение.

## Что исправлено в предварительном плане (`plan/code-review-d34e278.md`)

- **Сценарии.** Падают три сценария, а не один. Объявлять `w2e` неиспользуемым в `downtown_props.json` нельзя:
  это выхолостит заявленную цель сценария, вместо этого нужна перекалибровка. Контракт `snapshotKeysUsed`
  ругается и на ключ, объявленный неиспользуемым, но давший строки. Этап перенесён после правки ядра. Перед
  `npm run build` нужен `core:build:node`. Добавлены С4 и С5. Шаг «повторить `npm run release` в движке» убран из
  действий исполнителя.
- **Бустер.** Неверна причина: дело не в «скорости до импульсов тяги», а в демпфировании Rapier. Смещение
  прошлого шага равно `v_start·(1 + linear·dt)·dt`; измерено отношение 1.02497 при расчётном 1.025. Рекомендованное
  поле `prev_center` в `LevelState` противоречит задокументированному решению: `docs/en/core.md` — «The boost
  entry has no state… A latch was rejected». Кроме того, оно дублирует `LevelState.prev_cell`, а та к моменту
  `boost_dv` уже перезаписана текущей клеткой (`update_levels` идёт до `tank.update`). Новое исправление обходится
  без состояния: поправка проекции на демпфирование. Rust-тест больше не требует править скорость фикстуры.
- **Конфиг вспышек.** Цвета трассера входят в тот же «рецепт». В таблице `impactFlash` в docs `sideWidth` не
  упоминается, так что править docs не нужно. Довод «на `sideLength: 0` есть тест» после этапа 6 перестал бы быть
  верным.
- **Эффекты.** Тригонометрических вызовов 72, а не 36. `flatMap` аллоцирует на кадр больше исходного цикла, его
  заменил цикл с `push`. Проверка `rng` у клуба стала строже: сверяется конкретное значение.
- **Тесты.** Порог разгона сравнивал путь со скоростью, теперь у него верная размерность. Замена
  `{ ...impactFlash, sideLength: 0 }` по-прежнему требовала импорт `impactFlash`, а план предлагал его убрать —
  противоречие снято.
- **Общее.** У проекта нет `.prettierrc`, действует `~/.prettierrc.mjs`. Rust-код не приведён к `rustfmt` по
  умолчанию, поэтому `rustfmt` не запускать.

## Общие правила для исполнителя

1. **Никаких `git commit`/`push`/`merge`/`rebase`.** Релиз движка (`npm run release` в `../vimp`) не запускать.
2. **JS**: ES-модули, `===`, только `let`/`const`, фигурные скобки обязательны, в именах нет двух заглавных подряд
   (кроме констант `UPPER_SNAKE_CASE`). Комментарии — по-русски, в стиле окружающего кода. Форматирование — по
   `~/.prettierrc.mjs`: `printWidth` 80, `singleQuote`, `trailingComma: 'all'`, `arrowParens: 'avoid'`, `semi`.
   Своего `.prettierrc` у проекта нет. Форматтер не запускать, код сразу писать отформатированным.
3. **Rust**: стиль окружающего кода. `rustfmt.toml` в репозитории нет, а код не приведён к `rustfmt` по
   умолчанию, поэтому `cargo fmt` и `rustfmt` **не запускать**: иначе переформатируются чужие строки.
   Комментарии — по-русски.
4. **Markdown prettier'ом не форматировать.** Иначе он перепишет таблицы целиком.
5. **Документация**: `docs/en/*` и `CHANGELOG.md` — по-английски, `docs/ru/*` — по-русски. Пара en/ru
   обновляется в одном изменении. Какую страницу править, говорит таблица «Change → Page» в `CLAUDE.md`. Записи
   CHANGELOG идут под `## [Unreleased]`, тесты, рефакторинг и `docs/` туда не записываются. Порядок подразделов —
   Keep a Changelog: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`.
6. **Проверки в конце каждого этапа** (тихие флаги): `npx eslint . --quiet` и `npx vitest run --reporter=dot`.
   После правок в `core/` — ещё `cargo test --workspace -q` (то же, что `npm run core:test`) и `npm run core:build`:
   JS-тесты ядра грузят `core/pkg-node/`. Если тихий прогон упал, перезапустить только упавший тест с подробным
   выводом (`npx vitest run <файл> -t '<имя>'`, `cargo test <имя> -- --nocapture`).
7. **Место правки искать по фрагменту кода** (`grep -n`). Номера строк в этапах даны по HEAD `d34e278` и сдвигаются
   после правок.
8. **Временные файлы и эксперименты** — вне репозитория, во временном каталоге сессии. Отчёты `vimp-sim` писать
   через `--out <каталог>` или в `.debug/`: он в `.gitignore`.

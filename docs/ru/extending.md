# Расширение игры

Гайды по добавлению контента в `vimp-tanks`. Общее правило проекта: новые
сущности выполняются в едином стиле с существующими (фиксированного
контракта нет — существующие файлы служат образцом), а любое изменение
завершается зелёными `npx eslint .` и `npm test`, с покрытием нового кода
тестами.

## Новая карта

1. Создайте `src/data/maps/<имя>.js` по образцу существующих (например
   `pool_mini.js`). Формат:
   - `setId` — snapshot-ключ конструктора карты (`c1`/`c2`);
   - `scale` — масштаб карты;
   - `spriteSheet` — изображение тайлов и кадры `[x, y, w, h]`;
   - `layers` — распределение тайлов по слоям отрисовки (1 — под
     танками, 2 — уровень танков, 3+ — над);
   - `physicsStatic` — номера тайлов, являющихся стенами (по ним строится
     статическая физика и клиентский raycast);
   - `physicsDynamic` — динамические физические объекты (двигаются,
     передаются в снапшоте);
   - `step` — размер тайла;
   - `respawns` — точки возрождения по командам: массивы `[x, y, угол]`;
   - `map` — матрица тайлов.
2. Зарегистрируйте карту в `src/data/maps/index.js` — ключ объекта
   станет её названием в голосованиях и в настройках комнаты. Каталог
   карт движкового мастера читает те же данные (перезапуск мастера
   обновит выдачу).

## Новое оружие

Существует два архитектурно разных типа (см. [core.md](core.md)):

- **Hitscan** (пример `w1`): попадание рассчитывается мгновенно лучом
  (`castRay` в ядре); физического снаряда нет — только результат.
- **Explosive** (пример `w2`): в мире Rapier создаётся физический снаряд
  (`Bomb`), живёт в физическом цикле, передаётся клиенту как сущность
  снапшота, взрывается по таймеру.

Шаги:

1. Определите оружие в `src/data/weapons.js` (тип, урон, кулдаун, расход
   и т.д.) — эти данные уходят и в ядро (`buildCoreConfig`), и клиенту.
2. Реализуйте авторитетную часть в Rust-крейте этой игры (`core/src/`:
   `tanks.rs`, `tank.rs`, при необходимости — своя сущность по образцу
   `bomb.rs`) по аналогии с существующим оружием того же типа. Упаковка
   блока (`SnapshotPacker`) живёт в движковом крейте
   (`vimp_engine_core::snapshot`) — эта игра лишь поставляет строки по
   своей схеме `SnapshotConfig`.
3. Создайте клиентский рендеринг в `src/client/parts/`.
4. Зарегистрируйте сущность в `src/config/client.js`: `parts.gameSets`
   (snapshot-ключ → классы) и `parts.entitiesOnCanvas` (класс →
   полотно).
5. Зарегистрируйте snapshot-ключи оружия (и его эффектов) в
   `src/config/snapshot.js` — незарегистрированный ключ уронит упаковку
   кадра. Если существующие значения `kind` не подходят под форму
   данных, нужно добавить новую раскладку блока в движковый
   `snapshot.rs` и зеркально в его клиентский декодер `client/unpack.rs`,
   подняв версию формата — это изменение в репозитории движка,
   согласуйте его там.
6. Передавайте **id автора** последним элементом данных события/сущности
   (как `shooterId` у `w1` и `ownerId` у `w2`) — по нему клиентское ядро
   этой игры (`core/src/client/shot.rs`) подавляет авторитетные дубли
   клиентского спавна; типы `hitscan`/`explosive` оно поддерживает
   автоматически по конфигу оружия.
7. Добавьте боезапас в `src/config/game.js` (`panel`) и ключ панели в
   `src/config/client.js` (`modules.panel`).

## Новый звук

1. Добавьте запись в `src/config/sounds.js`: `file`, `priority`,
   `volume`, опционально `loop`.
2. Положите исходный файл в `assets/audio-raw/` и выполните `npm run
   game:build` — `audio:process` нормализует его (ffmpeg) и выпускает
   **`.webm` и `.mp3`** (список кодеков — `codecList`) в `dist/sounds/`,
   раздаваемый через `assetsBase`.
3. Воспроизведение: UI/системные звуки — `soundManager.playSystemSound(name)`;
   пространственные — `registerSound(name, { position })` (лимит голосов
   и приоритеты обрабатывает движковый `SoundManager`, см. движковый
   [client.md](https://github.com/lgick/vimp-engine/blob/main/docs/ru/client.md#soundmanager)).

## Новая клиентская сущность (part)

1. Создайте класс в `src/client/parts/` по образцу существующих (`Tank`,
   `Bomb`, эффекты в `parts/effects/`) и экспортируйте его из
   `parts/index.js` — он попадёт в движковый реестр `Factory`.
2. Пропишите её в `gameSets`/`entitiesOnCanvas` (`src/config/client.js`).
3. Если нужна процедурная текстура, добавьте baker в
   `src/client/bakers/` (по образцу существующих) и запись в
   `bakedAssets`.
4. Если нужны сервисы (`renderer`, `soundManager`), добавьте класс в
   `componentDependencies`.

Сущности можно наследовать и отображать на разных полотнах: например,
для радара создаётся упрощённый класс (как `MapRadar` от `Map`).

## Тесты

Новый код покрывается тестами в `tests/` (структура зеркалит `src/`).
Паттерны — собственные соглашения этого репозитория (зеркалящие
движковые): синглтоны через `vi.resetModules()` + динамический import;
логика ядра — Rust-тесты (`cargo test`) + JS↔WASM харнесс в
`tests/core/`; интеграция host-фасада — `tests/host/HostGame.test.js`
поверх реального `core/pkg-node`. Изменение модели движения танка
требует прогона cargo-паритета реплики предикта (`npm run core:test`).

# Игровой процесс

Командный танковый deathmatch: две команды (`team1`, `team2`) сражаются
раунд за раундом, третья «команда» — наблюдатели (`spectators`). Все
правила авторитетны на хосте комнаты (движковый
[host.md](https://github.com/lgick/vimp-engine/blob/main/docs/ru/host.md)).

## Путь игрока

1. **Подключение и авторизация** — ник не вводится; он берётся из identity игрока в лобби (центральный auth-сервис, проверяется по JWT), поэтому стартовая страница комнаты — информационная (заголовок + справка по управлению) с кнопкой **Start**. Единственный параметр формы — модель танка (по умолчанию `m1`), валидируется на хосте через `isValidModel`. Лимит комнаты (`maxPlayers`) считается **по людям** (боты уступают место); полная комната отвечает `roomFull`, очереди ожидания нет (см. движковый host.md).
2. **Наблюдатель** — после загрузки карты игрок попадает в игру спектатором: видит мир, камера следует за наблюдаемым игроком, клавиши `n`/`p` переключают цель наблюдения. Сразу приходит окно выбора команды.
3. **Выбор команды** — через меню голосования (`m` → Switch team). Если в команде нет свободных респаунов, хост пытается вытеснить бота; иначе — отказ («Team ... is full»).
4. **Игра** — в начале раунда игрок получает танк на респауне. В первые `teamChangeGracePeriod` (10 с) раунда смена команды применяется немедленно; позже игрок доигрывает раунд (или уходит в наблюдатели), и смена вступает в силу со следующего раунда.
5. **Смерть** — игрок становится наблюдателем до конца раунда, камера переключается на убийцу.

## Раунды и победа

- **Раунд** длится `roundTime` (по умолчанию 2 минуты). Победа — **team wipe**: уничтожение всех участников команды противника (боты считаются). Победившая команда получает командный фраг (`score +1` в шапке), проигравшая — поражение (`deaths +1`); всем проигрывается звук victory/defeat и показывается «{team} WINS!».
- Если время раунда истекло без победителя, начинается новый раунд без начисления очков.
- Между раундами пауза `roundRestartDelay` (5 с). В начале раунда мир пересоздаётся: все живы, панель сбрасывается к дефолтным значениям, респауны раздаются по командам.
- **Карта** живёт `mapTime` (10 минут). По истечении хост автоматически запускает голосование за следующую карту (`mapsInVote` вариантов); если никто не проголосовал, время текущей карты продлевается.

## Статистика (Tab)

Правила начисления очков (движковый `RoundManager.reportKill`,
`packages/engine/src/host/meta/core/RoundManager.js`):

1. Уничтоженный игрок получает поражение (`deaths +1`) и статус `dead` до конца раунда.
2. Уничтоживший соперника получает фраг (`score +1`).
3. Уничтоживший игрока **своей** команды теряет фраг (`score −1`).
4. Самоубийство — только поражение (`deaths +1`), фраги не изменяются.
5. За team wipe команда-победитель получает `score +1`, проигравшая — `deaths +1` (итоги показаны в шапке таблицы).
6. Столбец `latency` — текущий RTT игрока (у ботов пусто).

Изменения статистики рассылаются в момент появления; сортировка таблицы происходит на клиенте (`score` по убыванию, затем `deaths` по возрастанию). Сами столбцы — схема этой игры, см. [configuration.md](configuration.md#stats-stat).

## Голосования (клавиша `m`)

Движковая система коллективных решений (`Vote` + `VoteCoordinator` в
`packages/engine/src/host/meta/`):

- **Меню** — окно с пунктами «Switch team» и «Suggest map».
- **Запуск игроком или системой** — предложение карты игроком (если этот игрок в игре один, карта меняется сразу, без голосования), голосование за ботов, автоматический выбор карты по таймеру.
- **Очередь** — голосование, созданное во время активного, ставится в очередь и запускается после.
- **Кулдаун** — после голосования на тему действует блокировка `timeBlockedVote` (30 с) от спама.
- **Время жизни** — `voteTime` (10 с); окна с `timeOff: true` (меню) не закрываются по таймеру.
- **Пагинация** — списки длиннее 7 разбиваются на страницы (Back/More).
- **Ничья** — победитель выбирается случайно среди набравших максимум.

Механизм голосования принадлежит движку; эта игра лишь поставляет
шаблоны/меню и создаёт динамические голосования (например, `/bot`) через
`ctx.voteCoordinator.createVote(...)`. Формат обмена — движковый
[network.md](https://github.com/lgick/vimp-engine/blob/main/docs/ru/network.md#голосование-порт-16).

## Чат (клавиша `c`) и команды

Обычный текст — сообщение команде/всем (длина ограничена хостом, 60 символов). Сообщения, начинающиеся с `/`, — команды (движковый `CommandProcessor`, плюс `/bot` этой игры, зарегистрированный через `HostPlugin.chatCommands`):

| Команда | Владелец | Действие |
| --- | --- | --- |
| `/name <ник>` | движок | Смена имени (с проверкой и системным сообщением) |
| `/timeleft` | движок | Оставшееся время карты |
| `/mapname` | движок | Название текущей карты |
| `/rank` | движок | Текущий ранг (подгружается с auth-сервиса) |
| `/bot <N> [team]` | эта игра | Создать N ботов (в команду или с равномерным распределением); `/bot 0 [team]` — удалить ботов |
| `/nr` | движок | Новый раунд — **только в dev-режиме** |
| `/ban <причина>` | движок | Жалоба на хост комнаты (соц-модерация P2P) — **не идёт хосту**, см. ниже |

`/bot` доступен только активным игрокам. Если активных людей больше
одного, вместо немедленного исполнения запускается голосование;
исполнение команды перезапускает раунд.

**`/ban <причина>`** — единственная анти-чит-мера: браузерный хост
исполняет симуляцию у себя и физически может читерить (модифицированный
клиент правит WASM-память в обход логики ядра), поэтому модерация
социальная, а не техническая. Команда перехватывается **на клиенте** и
уходит напрямую мастер-серверу по сигнальному WS (минуя хоста — его
`CommandProcessor` мог бы отфильтровать жалобу на самого себя), не через
игровой протокол. Причина обязательна (иначе появляется локальная
подсказка в чате) и публично не отображается. Доступна только гостям
комнаты (у хоста-игрока такой опции нет); при разорванном соединении с
мастером в чате появляется сообщение об ошибке. Мастер учитывает только
жалобы от игроков, реально подключавшихся к этой комнате. При достижении
порога уникальных по IP жалоб мастер банит комнату: она исчезает из
списка серверов, сигнальный WS хоста закрывается (новые игроки не могут
до него достучаться; уже подключённые P2P-пиры остаются — host-migration
нет). Детали — движковый
[master.md](https://github.com/lgick/vimp-engine/blob/main/docs/ru/master.md#соц-модерация-ban)
(соц-модерация `/ban`).

## Управление

Наборы клавиш переключает хост по статусу (наблюдатель/игрок):

- **Наблюдатель**: `n` — следующий игрок, `p` — предыдущий.
- **Игрок**: `w/s` — газ/назад, `a/d` — поворот, `k/l` — поворот башни, `u` — башня в центр, `j` — огонь, `n/p` — следующее/предыдущее оружие.
- **Режимы** (в любом статусе): `c` — чат, `m` — голосование, `Tab` — статистика; `Esc`/`Enter` — управление внутри режимов.

Раскладка клавиш настраивается в `src/config/client.js` (`modules.controls`), команды и их типы — в `src/config/game.js` (`playerKeys`), см. [configuration.md](configuration.md#клавиши-playerkeys).

## Оружие и танк

У танка два оружия (переключение `n`/`p`, активное подсвечено на панели):

- **`w1` — пуля (hitscan)**: мгновенный луч, урон 40, дальность 1500, боезапас 200. Попадание считает хост лучом; клиент рисует трассер немедленно.
- **`w2` — бомба (explosive)**: физический снаряд, закладывается и детонирует по таймеру; урон 70 в эпицентре с падением по радиусу 50, боезапас 100.

Здоровье — 100. Состояние танка (`condition`) визуально деградирует с уроном (дым), при 0 танк уничтожен. Характеристики — [configuration.md](configuration.md#weaponsjs).

## Панель HUD

Слева направо: время раунда, здоровье, боезапас `w1`/`w2` (активное оружие подсвечивается). Наблюдателям значения скрыты (пустая панель). Значения сбрасываются к дефолтным каждый раунд.

## Боты

ИИ живёт в Rust-ядре этой игры ([core.md](core.md)): боты — полноценные
участники — попадают в статистику, водят танки и стреляют через тот же
ввод, что и игроки. Навигация — движковый поиск пути по сетке карты плюс
пространственная сетка для поиска целей. Добавляются `/bot` или
голосованием; бот вытесняется при заходе человека в полную команду
(также при подключении человека сверх суммарного лимита `maxPlayers`).

## Кики

- **Бездействие**: игрок без ввода/чата дольше `idleKickTimeout.player` (2 мин) кикается (наблюдатели — нет, по умолчанию `null`).
- **Сеть**: сглаженная (EMA) задержка выше `maxLatency` (1000 мс — порог рассчитан на P2P-хостинг с домашних каналов) или `maxMissedPings` (5) пропущенных пингов подряд — соединение закрывается с техническим сообщением.

Эти политики киков — движковый механизм, см. движковый
[configuration.md](https://github.com/lgick/vimp-engine/blob/main/docs/ru/configuration.md#кики-rtt-idlekicktimeout).

## Карты

`pool mini`, `canopy`, `garden` — тайловые карты с респаунами по
командам, статической геометрией и динамическими объектами (передаются
в снапшоте). Смена — голосованием или по таймеру карты. Добавление
новой — [extending.md](extending.md#новая-карта).
